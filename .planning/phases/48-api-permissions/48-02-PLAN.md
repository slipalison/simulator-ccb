**Part A: Add Fundo and Cedente endpoints to FundosController**

Add the following endpoints to the existing FundosController created in Plan 01. They follow the exact same pattern as ConsultoriaFundo/Custodiante endpoints.

**Fundo endpoints:**

1. `POST /api/fundos` — Register Fundo (CAD-09)
   - `[Authorize(AuthenticationSchemes = "BearerClient", Policy = PermissionPolicies.FundWrite)]`
   - Request body: `{ Nome, Cnpj, ConsultoriaFundoId, CustodianteId, TipoFundo, ClasseAnbima?, Segmento?, DataConstituicao? }`
   - Actor info from ICurrentCompanyService + JWT claims
   - DuplicateEntityException → 409, KeyNotFoundException → 404 (FK references not found)
   - Note: Fundo always starts with RASCUNHO status (enforced by domain)

2. `GET /api/fundos` — List Fundo with pagination (CAD-10)
   - `[Authorize(AuthenticationSchemes = "BearerClient", Policy = PermissionPolicies.FundRead)]`
   - Query params: page, pageSize, search

3. `GET /api/fundos/{id:guid}` — Get Fundo by ID
   - `[Authorize(AuthenticationSchemes = "BearerClient", Policy = PermissionPolicies.FundRead)]`

4. `PUT /api/fundos/{id:guid}` — Update Fundo data (CAD-11)
   - `[Authorize(AuthenticationSchemes = "BearerClient", Policy = PermissionPolicies.FundWrite)]`
   - Request body: `{ Nome, ClasseAnbima?, Segmento?, DataConstituicao? }`
   - Note: Status is NOT updated here — use TransitionFundoStatus endpoint

5. `POST /api/fundos/{id:guid}/status` — Transition Fundo status (CAD-13)
   - `[Authorize(AuthenticationSchemes = "BearerClient", Policy = PermissionPolicies.FundWrite)]`
   - Request body: `{ NewStatus }` where NewStatus is FundoStatus enum value (integer or string)
   - Catches InvalidStateTransitionException → 400 BadRequest with transition info
   - Catches KeyNotFoundException → 404

**Cedente endpoints:**

6. `POST /api/fundos/cedentes/pf` — Register Cedente PF (CAD-14)

   - DuplicateEntityException → 409

7. `POST /api/fundos/cedentes/pj` — Register Cedente PJ (CAD-15)
   - `[Authorize(AuthenticationSchemes = "BearerClient", Policy = PermissionPolicies.FundWrite)]`
   - Request body: `{ Cnpj, RazaoSocial, Email?, Telefone?, Endereco? }`
   - DuplicateEntityException → 409

8. `GET /api/fundos/cedentes` — List Cedente with pagination (CAD-16)
   - `[Authorize(AuthenticationSchemes = "BearerClient", Policy = PermissionPolicies.FundRead)]`

**Part A: Create admin listing query handlers (per D-13 — deferred from Phase 46/47)**

Create admin query handlers in `src/Onboarding.Application/Fundos/Queries/Admin/` that bypass HasQueryFilter for cross-company visibility. These follow the same pattern as existing admin query handlers in `src/Onboarding.Application/Admin/Queries/`.

Each admin query handler:
- Does NOT inject ICurrentCompanyService (no company filter)
- Calls repository methods with IgnoreQueryFilters (e.g., `_context.Fundos.IgnoreQueryFilters().Where(...)`)
- Returns paginated results with company name/id included (for cross-company visibility)
- Is registered in DependencyInjection.cs as `IQueryHandler<XQuery, PaginatedResult<XDto>>`

   - Adds CompanyName

3. `ListCustodiantesAdminQuery(Page, PageSize, Search?)` → `PaginatedResult<CustodianteAdminDto>`
   - Adds CompanyName

4. `ListCedentesAdminQuery(Page, PageSize, Search?)` → `PaginatedResult<CedenteAdminDto>`
   - Adds CompanyName
