# Plan 21-02 — Frontend Client + Backoffice Jobs: Vinxi Build, ESLint, TypeScript Validation

## Overview

Add two independent frontend jobs to `.github/workflows/ci.yml`: `frontend-client` and `frontend-backoffice`. Each job validates the full build pipeline: npm dependency installation, TypeScript type checking, ESLint zero-warning enforcement, and Vinxi production build.

**Critical prerequisite:** ESLint is not installed in either frontend project. This plan includes ESLint installation and flat config setup as the first task — the CI lint step cannot run without it.

## Success Criteria

1. ✅ `frontend-client` job runs: checkout → setup Node.js → cache npm → `npm ci` → `tsc --noEmit` → `eslint . --max-warnings 0` → `npm run build`
2. ✅ `frontend-backoffice` job runs same pipeline independently
3. ✅ Both jobs run in parallel with no `needs:` dependency on each other or the backend job
4. ✅ ESLint installed and configured in both frontend projects with zero warnings on current codebase
5. ✅ `tsc --noEmit` passes with no type errors in both projects
6. ✅ `vinxi build` completes successfully in both projects, producing `.output/` directories
7. ✅ npm caching configured with `actions/cache@v5` keyed on per-project `package-lock.json`

## Technical Details

### ESLint Installation (Both Projects)

ESLint 9.x uses flat config (`eslint.config.js` or `eslint.config.mjs`). The project uses React 19, TypeScript 5.7, and Vinxi (Vite-based).

**Packages to install:**
```bash
npm install --save-dev eslint@^9 @eslint/js typescript-eslint @typescript-eslint/parser @typescript-eslint/eslint-plugin eslint-plugin-react-hooks eslint-plugin-react-refresh
```

**Flat config scaffold (`eslint.config.mjs`):**
```js
import js from '@eslint/js';
import tseslint from 'typescript-eslint';
import reactHooks from 'eslint-plugin-react-hooks';
import reactRefresh from 'eslint-plugin-react-refresh';

export default tseslint.config(
  { ignores: ['dist', '.vinxi', '.output', 'node_modules'] },
  {
    files: ['**/*.{ts,tsx}'],
    extends: [
      js.configs.recommended,
      ...tseslint.configs.recommended,
    ],
    plugins: {
      'react-hooks': reactHooks,
      'react-refresh': reactRefresh,
    },
    rules: {
      'react-hooks/rules-of-hooks': 'error',
      'react-hooks/exhaustive-deps': 'warn',
      'react-refresh/only-export-components': [
        'warn',
        { allowConstantExport: true },
      ],
      '@typescript-eslint/no-explicit-any': 'warn',
    },
  },
);
```

**Important:** The current codebase has multiple `// eslint-disable-next-line @typescript-eslint/no-explicit-any` comments. The config above sets `no-explicit-any` to `warn` (not `error`) so existing disables don't cause failures. The CI uses `--max-warnings 0`, so `warn`-level rules WILL fail. 

**Resolution:** Either:
1. Set `no-explicit-any` to `off` initially (recommended for Phase 21 — get CI passing first, tighten later)
2. Keep as `warn` and remove all `eslint-disable-next-line` comments (they become unnecessary)

**Recommended approach:** Set to `off` for initial CI setup. The `eslint-disable-next-line` comments are harmless noise. Tightening `no-explicit-any` is a separate code quality task.

### npm Add Scripts

Add to both `package.json` files:
```json
{
  "scripts": {
    "lint": "eslint . --max-warnings 0",
    "typecheck": "tsc --noEmit"
  }
}
```

### Workflow Jobs Structure

```yaml
  frontend-client:
    name: Frontend Client (Vinxi)
    runs-on: ubuntu-latest
    permissions:
      contents: read
    defaults:
      run:
        working-directory: frontend/client
    steps:
      - uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: "22"

      - name: Cache npm
        uses: actions/cache@v5
        with:
          path: ~/.npm
          key: ${{ runner.os }}-npm-client-${{ hashFiles('frontend/client/package-lock.json') }}
          restore-keys: |
            ${{ runner.os }}-npm-client-

      - name: Install dependencies
        run: npm ci

      - name: Type check
        run: npx tsc --noEmit

      - name: Lint
        run: npx eslint . --max-warnings 0

      - name: Build
        run: npm run build

  frontend-backoffice:
    name: Frontend Backoffice (Vinxi)
    runs-on: ubuntu-latest
    permissions:
      contents: read
    defaults:
      run:
        working-directory: frontend/backoffice
    steps:
      - uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: "22"

      - name: Cache npm
        uses: actions/cache@v5
        with:
          path: ~/.npm
          key: ${{ runner.os }}-npm-backoffice-${{ hashFiles('frontend/backoffice/package-lock.json') }}
          restore-keys: |
            ${{ runner.os }}-npm-backoffice-

      - name: Install dependencies
        run: npm ci

      - name: Type check
        run: npx tsc --noEmit

      - name: Lint
        run: npx eslint . --max-warnings 0

      - name: Build
        run: npm run build
```

### Step Order Rationale

1. `npm ci` — deterministic install from lockfile (fastest with warm npm cache)
2. `tsc --noEmit` — catches type errors before lint (fail fast, type errors are cheaper to fix)
3. `eslint . --max-warnings 0` — code quality gate (style, anti-patterns, hooks rules)
4. `npm run build` — full Vinxi compilation (most expensive step, only runs if prior steps pass)

## Risk Assessment

| Risk | Probability | Impact | Mitigation |
|------|------------|--------|------------|
| Existing code has ESLint warnings that block CI | High | High | Set rules to `warn` instead of `error` for rules with existing violations. Run `eslint --fix` for auto-fixable issues. Address manually for complex violations. |
| `tsc --noEmit` fails due to missing route types (TanStack Router codegen) | Medium | Medium | TanStack Router generates `routeTree.gen.ts`. Run `vinxi dev` or `vinxi build` first to generate types, then `tsc --noEmit`. If types are generated during build, reorder steps: build first, then typecheck. |
| `vinxi build` fails in CI due to missing env vars | Low | Medium | Research confirms no special env vars needed on `ubuntu-latest`. If build fails, check `NODE_ENV` — set to `production` explicitly in workflow. |
| ESLint flat config conflicts with Vinxi/Vite setup | Low | Low | Use standard TypeScript + React flat config. Vinxi doesn't interfere with ESLint. Vite-specific plugins not needed for ESLint. |
| npm cache corruption between runs | Low | Low | `npm ci` is deterministic — it deletes `node_modules` and reinstalls from lockfile. Corrupted cache causes `npm ci` to fail, but `actions/cache` handles this by skipping cache restore on miss. |
| `actions/cache@v5` not compatible with GitHub runner version | Low | Low | If runner < 2.327.1, fall back to `actions/cache@v4`. Can detect via workflow condition. |
