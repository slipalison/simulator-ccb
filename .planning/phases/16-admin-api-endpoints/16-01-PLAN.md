### Task 2: Client Entity — DeletedAt + Anonymize()

**Type:** Domain
**Scope:** `Onboarding.Domain/Aggregates/ClientAggregate/Client.cs`

Extend the `Client` aggregate with soft-delete support for LGPD compliance.

**Changes to make:**
1. Add `public DateTime? DeletedAt { get; private set; }` property
2. Add `public bool IsDeleted => DeletedAt.HasValue;` computed property
3. Add `public void Anonymize()` method that:
   - Returns early if already deleted (idempotent guard)
   - Sets `DeletedAt = DateTime.UtcNow`
   - Sets `Name = "Usuário Excluído"`
   - Sets `Email` to `deleted-{id}@internal.local`
   - Sets `Phone` to `+0000000000`
   - Sets `Cpf = null`, `Cnpj = null`, `RazaoSocial = null`
4. Add `public void Update(string name, string? razaoSocial, string email, string phone)` method for ADMIN-03

**IMPORTANT:** `Anonymize()` must handle value objects correctly — use `Email.Create()` and `PhoneNumber.Create()` for the placeholder values. Do NOT assign strings directly to value object properties.

**Verification:**
- `dotnet build` succeeds
- `Client.Anonymize()` is idempotent — calling twice does not change state further
- `Client.Update()` validates inputs (throws `ArgumentException` for null/empty name)
- Existing factory methods (`RegisterPessoaFisica`, `RegisterPessoaJuridica`) unchanged

### Task 9: Add Keycloak.AuthServices.Authorization Package

**Type:** Infrastructure
**Scope:** `Onboarding.API.csproj` + `Program.cs`

Add the package that enables `[Authorize(Roles = "admin")]` with Keycloak JWT.

**Steps:**
1. Add package: `Keycloak.AuthServices.Authorization` version 2.9.0 to `Onboarding.API.csproj`
2. In `Program.cs`, after `AddAuthentication` + `AddJwtBearer`, add:
   ```csharp
   // Keycloak role-based authorization — transforms resource_access roles to flat role claims
   builder.Services.AddTransient<IClaimsTransformation, KeycloakRolesClaimsTransformation>(sp =>
       new KeycloakRolesClaimsTransformation("onboarding-api")); // client name in Keycloak
   ```
3. Add using: `using Keycloak.AuthServices.Authorization;`

**IMPORTANT:** The client name `"onboarding-api"` must match the Keycloak client that has the `admin` role configured. This is the confidential client `onboarding-api-admin` in the realm, but the resource_access key in the JWT will be the client ID — verify which name Keycloak uses.

**Verification:**
- `dotnet build` succeeds
- Package reference appears in `Onboarding.API.csproj`
- `KeycloakRolesClaimsTransformation` is registered as transient
- No duplicate registration of auth middleware
