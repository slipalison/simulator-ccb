| Step | Description | Status | Details |

## 2. Cross-Phase Wiring Gaps

### Gap 1: Password Reset Link — Hardcoded Port (CRITICAL)
- **File:** `D:\REPO\keycloak-tests\src\Onboarding.Application\Auth\Commands\ForgotPasswordCommand.cs` line 55
- **Issue:** `var resetLink = $"http://localhost:3001/reset-password?token={token.Token}";`
- **Impact:** Password reset emails contain broken links. User cannot reset password.
- **Fix:** Read frontend base URL from configuration: `configuration["Frontend:BaseUrl"] ?? "http://localhost:5173"`

### Gap 2: Registration API → Frontend Route Path (LOW RISK)
- **Frontend calls:** `POST /api/registration` (lowercase)
- **Backend route:** `[Route("api/[controller]")]` on `RegistrationController` → resolves to `/api/Registration` in .NET default
- **Analysis:** ASP.NET Core routing is case-insensitive by default, so `/api/registration` matches `/api/Registration`. **No issue in practice**, but worth noting the controller could be made explicit with `[Route("api/registration")]` for clarity.

### Gap 3: Cookie `Secure` Flag Always False (MODERATE)
- **File:** `D:\REPO\keycloak-tests\src\Onboarding.API\Controllers\AuthController.cs` — login, refresh, and me endpoints
- **Issue:** `Secure = false` is hardcoded with a comment `// true in production (HTTPS)`. No environment-based toggling exists.
- **Impact:** In production without HTTPS, cookies would be sent over plain text. The code comment acknowledges this, but there is no runtime configuration to change it.
- **Fix:** `Secure = builder.Environment.IsProduction()` or read from config.

### Gap 4: `client.tsx` is a Confirmed Orphan Placeholder
- **File:** `D:\REPO\keycloak-tests\frontend\src\client.tsx`
- **Issue:** This file renders a basic `<h1>Onboarding</h1><p>Infrastructure phase — placeholder</p>`. The actual SPA entry point is `main.tsx` which uses `RouterProvider` with TanStack Router.
- **Confirmed:** `index.html` references `./src/main.tsx` (line 10), NOT `client.tsx`. The `client.tsx` file is a true orphan with no imports and should be deleted.

### Gap 5: No `AuthGuard` Component Usage in Router
- **Issue:** The `AuthGuard` component exists at `frontend/src/components/guards/AuthGuard.tsx` but is not used in `router.tsx`. ProfilePage implements its own inline auth guard logic.
- **Impact:** Not a bug — the inline guard works. But `AuthGuard` is orphan/unused code.

### Gap 6: Forgot Password Rate Limit (3/hour) vs AuthController Rate Limit (429)
- The `ForgotPasswordCommandHandler` enforces a 3-per-hour limit by querying the DB, but the `AuthController.ForgotPassword` endpoint correctly catches `RateLimitExceededException` and returns 429. This is properly wired.

## 4. Security Concerns

### 4.1 Cookie `Secure` Flag — Always False (MODERATE)
- **Location:** `AuthController.cs` — login, refresh, me endpoints
- **Risk:** Refresh tokens transmitted in cookies without `Secure` flag would be vulnerable to interception over HTTP.
- **Current State:** Acceptable for local development only. Must be environment-aware for production.

### 4.2 Cookie `SameSite=Lax` (LOW)
- `SameSiteMode.Lax` is appropriate for this use case. It allows cookies on top-level GET navigations and blocks on cross-site POST requests. Since all API calls are same-site (proxied through Vinxi), this is correct.

### 4.3 CORS Configuration (OK)
- `AllowFrontendWithCredentials` policy:
  - Origin: `http://localhost:5173` only
  - `AllowCredentials()`: enabled
  - No `AllowAnyOrigin()` — correct
- Middleware order: `UseCors` → `UseAuthentication` → `UseAuthorization` — correct

### 4.4 Server Proxy — Cookie Forwarding (OK)
- `server.ts` correctly forwards `Set-Cookie` headers from backend to browser
- Splits multiple cookies correctly with regex `,(?=\s*\w+=)`
- Forwards request cookies from browser to backend via `getHeaders()`

### 4.5 Token Storage (OK)
- Access tokens stored in module-level variable (memory-only) — NOT in `localStorage`
- Refresh tokens in `httpOnly` cookies — NOT accessible to JavaScript
- Proper defense against XSS

### 4.6 Password Reset Token in URL (LOW RISK)
- Reset token is passed as URL query param: `/reset-password?token=xxx`
- This is standard practice but tokens appear in browser history, server logs, and referrer headers
- Token expiry is 15 minutes (enforced in domain layer), which limits the window of exposure

### 4.7 Keycloak User Creation Compensation (OK)
- If Keycloak user creation fails after DB persist, the handler deletes the DB row
- If Keycloak user creation succeeds but password set fails, the exception propagates and the DB row remains (orphan client without Keycloak user)
- **Gap:** The `IsTransientKeycloakError` does NOT cover the password-set failure path explicitly. The `CreateUserAsync` method throws `InvalidOperationException` on password set failure, which IS caught by `IsTransientKeycloakError` (returns true for non-ArgumentException). Compensation runs correctly.

## 5. Recommendations

### P0 — Must Fix Before Release
1. **Fix password reset URL** — Replace hardcoded `localhost:3001` with configuration value. Add `Frontend__BaseUrl` to `appsettings.json` and `compose.yaml`.

### P1 — Should Fix
2. **Make cookie `Secure` flag environment-aware** — Read from config or use `Environment.IsProduction()`.
3. **Remove or repurpose `client.tsx`** — Either delete the orphan file or update `index.html` to reference `main.tsx` (or vice versa).
4. **Clean up duplicate test files** — Remove old pre-redesign tests or mark them as legacy.

### P2 — Nice to Have
5. **Use `AuthGuard` component in router** — Either wrap `/profile` route with `AuthGuard` in `router.tsx` or delete the unused component.
6. **Add `credentials: 'include'` to registration API call** — Currently `registerClient()` does not include `credentials: 'include'`. Not critical since registration doesn't use cookies, but for consistency.
7. **Add explicit route attribute** — Change `[Route("api/[controller]")]` to `[Route("api/registration")]` on `RegistrationController` for clarity.
8. **Consider SameSite=Strict for refresh cookie** — Since all API calls are same-origin via the proxy, `Strict` provides stronger CSRF protection than `Lax`.
9. **Add rate limiting middleware** — The forgot password endpoint has application-level rate limiting (3/hour per email), but no global rate limiting on login endpoint to prevent brute force.
