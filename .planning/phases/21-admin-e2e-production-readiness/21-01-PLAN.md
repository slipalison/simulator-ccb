# Phase 21 — Plan 01: Admin E2E Testing with Playwright

## Objective

Install Playwright no projeto `frontend/backoffice`, configurar infraestrutura de testes E2E (auth helpers, page objects, fixtures), e escrever testes end-to-end para todos os fluxos administrativos — garantindo que o sistema funciona de ponta a ponta como o usuário final experimentaria.

## Execution Context

**Strategy:** E2E-first — escrever testes contra o frontend real rodando em modo dev/test, sem mocks de UI (apenas fixtures de API quando necessário).

**Frontend context:** `frontend/backoffice/` já tem todas as páginas e componentes: login, list, detail, edit, block/unblock, delete dialogs.

**Backend context:** API já roda em `http://localhost:5000` (ou porta configurada). Admin endpoints protegidos com `[Authorize(Roles = "admin")]`.

**Keycloak context:** Precisa de admin user seed no Keycloak com role "admin" para login E2E. Verificar se existe ou criar.

**What needs to be added:**
- Playwright installation e config no backoffice
- Auth fixture (login as admin, store cookies)
- Page objects (LoginPage, UsersListPage, UserDetailPage, EditPage, Dialogs)
- E2E test specs para cada fluxo crítico
- CI-friendly test execution (`npx playwright test`)

**What NOT to touch:**
- Client frontend E2E (Phase 14, deferred)
- Backend code (already working)
- Unit tests (already 156 passing)

## Context

**Source:** `frontend/backoffice/` projeto atual

**Admin credentials for E2E:**
- Need admin user in Keycloak with `admin` role
- If not exists, will need to seed via Keycloak Admin API or manual setup
- Credentials stored in `.env.e2e` (gitignored)

**Backend API contracts (verified in Phase 16 & 20):**
```
POST /api/auth/admin/login → { accessToken, refreshToken }
GET /api/admin/users → paginated list
PUT /api/admin/users/{id} → partial update
POST /api/admin/users/{id}/block → { reason }
POST /api/admin/users/{id}/unblock → { reason? }
DELETE /api/admin/users/{id} → 204 No Content
```

**Prior decisions:**
- Admin auth via cookies httpOnly (Path=/api/admin)
- Admin cookie name: `adminRefreshToken`
- Sonner for toasts
- shadcn/ui components

## Tasks

### Task 1: Install Playwright
**Files:** `frontend/backoffice/package.json`, `frontend/backoffice/playwright.config.ts`

1. `cd frontend/backoffice && npm install -D @playwright/test`
2. `npx playwright install` (downloads browser binaries)
3. Create `playwright.config.ts`:
   - `testDir: './tests-e2e'`
   - `baseURL: process.env.BACKOFFICE_URL || 'http://localhost:5174'`
   - `retries: 1` (CI resilience)
   - `reporter: [['html'], ['list']]`
   - `use: { headless: true, baseURL, trace: 'on-first-retry' }`
4. Add `npm run test:e2e` → `playwright test` script to package.json
5. **Verify:** `npx playwright test --list` runs without errors (even with zero tests)

### Task 2: Create E2E Auth Fixture
**Files:** `frontend/backoffice/tests-e2e/fixtures/admin-auth.ts`

1. Create `adminLogin()` — calls backend `/api/auth/admin/login` directly, stores cookies
2. Create `adminLogout()` — clears cookies
3. Create `test.use({ storageState: 'tests-e2e/.auth/admin.json' })` pattern
4. Pre-auth state saved to `tests-e2e/.auth/admin.json` (gitignored)
5. Setup/teardown hooks: login before all tests, cleanup after
6. **Verify:** Auth fixture works, subsequent requests carry valid cookies

### Task 3: Create Page Objects
**Files:**
- `frontend/backoffice/tests-e2e/pages/login-page.ts`
- `frontend/backoffice/tests-e2e/pages/users-list-page.ts`
- `frontend/backoffice/tests-e2e/pages/user-detail-page.ts`
- `frontend/backoffice/tests-e2e/pages/user-edit-page.ts`
- `frontend/backoffice/tests-e2e/pages/dialogs.ts`

1. **LoginPage:** `goto()`, `fillEmail()`, `fillPassword()`, `clickLogin()`, `waitForSuccess()`
2. **UsersListPage:** `waitForLoad()`, `search(query)`, `filterStatus(status)`, `clickUser(id)`, `clickEdit(id)`, `clickBlock(id)`, `clickUnblock(id)`, `clickDelete(id)`, `getRowData(id)`, `waitForDeletedBadge(id)`
3. **UserDetailPage:** `waitForLoad()`, `getName()`, `getEmail()`, `getDocument()`, `clickEdit()`, `clickBlock()`, `clickUnblock()`, `clickDelete()`
4. **UserEditPage:** `waitForLoad()`, `fillName()`, `fillEmail()`, `fillPhone()`, `clickSave()`, `clickCancel()`, `waitForValidationError(field)`
5. **Dialogs:** `BlockDialog: fillReason()`, `confirm()`, `cancel()`, `waitForClose()`; `UnblockDialog: confirm()`, `cancel()`; `DeleteDialog: typeEmail()`, `confirm()`, `cancel()`, `waitForEmailMismatchError()`
6. **Verify:** Page objects compile, can be imported in test specs

### Task 4: E2E Test — Admin List Flow
**File:** `frontend/backoffice/tests-e2e/admin-list-flow.spec.ts`

1. **Test:** Admin logs in → redirected to `/admin/users` → table loads with users
2. **Test:** Admin searches by name → table filters in real-time (debounced)
3. **Test:** Admin filters by status (Active/Blocked/Deleted) → table updates
4. **Test:** Admin clicks user → navigates to `/admin/users/{id}` → detail page loads
5. **Test:** Admin navigates back → list page still shows filtered state
6. **Verify:** All 5 tests pass (GREEN)

### Task 5: E2E Test — Admin Edit Flow
**File:** `frontend/backoffice/tests-e2e/admin-edit-flow.spec.ts`

1. **Test:** Admin clicks Edit → navigates to `/admin/users/{id}/edit` → form populates
2. **Test:** Admin submits invalid email → inline validation error shown
3. **Test:** Admin submits invalid phone → inline validation error shown
4. **Test:** Admin submits valid changes → success toast → table refreshes with updated data
5. **Test:** Admin clicks Cancel → navigates back to detail page without saving
6. **Verify:** All 5 tests pass (GREEN)

### Task 6: E2E Test — Admin Block/Unblock Flow
**File:** `frontend/backoffice/tests-e2e/admin-block-unblock-flow.spec.ts`

1. **Test:** Admin clicks Block → dialog opens → type reason (< 10 chars) → button disabled
2. **Test:** Admin types valid reason (≥ 10 chars) → clicks Confirm → success toast → status shows "Blocked"
3. **Test:** Admin clicks Unblock → dialog opens → clicks Confirm (reason optional) → success toast → status shows "Active"
4. **Test:** Block from detail page → same flow, navigates back after success
5. **Test:** Blocked user cannot login (verify Keycloak user disabled) — optional, depends on Keycloak Admin API access
6. **Verify:** All 5 tests pass (GREEN)

### Task 7: E2E Test — Admin Delete Flow (LGPD)
**File:** `frontend/backoffice/tests-e2e/admin-delete-flow.spec.ts`

1. **Test:** Admin clicks Delete → dialog opens → type wrong email → button disabled
2. **Test:** Admin types correct email → button enabled → clicks Confirm → success toast → "Deleted" badge appears
3. **Test:** Deleted user row shows reduced opacity, all action buttons disabled
4. **Test:** Admin attempts to delete already-deleted user → 409 error toast "User already deleted"
5. **Test:** Delete from detail page → confirms → redirects to `/admin/users` list
6. **Verify:** All 5 tests pass (GREEN)

### Task 8: E2E Test — Admin 403 Flow
**File:** `frontend/backoffice/tests-e2e/admin-403-flow.spec.ts`

1. **Test:** Non-admin user logs in → attempts to access `/admin/users` → redirected to 403 Access Denied page
2. **Test:** Non-admin user directly accesses `/admin/users/{id}` → 403 page shown
3. **Test:** 403 page shows "You don't have permission to access this area" with link back to home
4. **Verify:** All 3 tests pass (GREEN)
