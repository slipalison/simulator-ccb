# Phase 20 — Plan 01: Edit User Form + Block/Unblock Dialog

## Objective

Implementar formulário de edição de usuário com validação Zod, dialogs de bloqueio/desbloqueio com campo reason obrigatório, e integração com a API admin — tudo no projeto `frontend/backoffice` separado.

## Execution Context

**Strategy:** Test-first — criar testes antes da implementação (padrão do projeto).

**Backend ready:** PUT /api/admin/users/{id}, POST /api/admin/users/{id}/block, POST /api/admin/users/{id}/unblock já existem (Phase 16).

**Frontend context:** `frontend/backoffice/` já tem listagem, detail page, admin auth, admin-api.ts com funções de list/detail.

**What needs to be added:**
- Edit form (RHF + Zod) para dados PF/PJ
- Block/Unblock dialogs com reason field
- API functions em `admin-api.ts` (editUser, blockUser, unblockUser)
- Route `/admin/users/$id/edit`
- Toast notifications + table refresh

**What NOT to touch:**
- LGPD deletion (Phase 20 Plan 02)
- Backend endpoints (já existem)
- Client frontend

## Context

**Source:** `frontend/backoffice/` projeto atual

**Backend API contracts (Phase 16):**
```
PUT /api/admin/users/{id}
  Body: { name?, email?, phone?, address? } (partial update)
  Response: 200 OK | 400 Validation Errors | 404 Not Found

POST /api/admin/users/{id}/block
  Body: { reason: string }
  Response: 200 OK | 404 Not Found

POST /api/admin/users/{id}/unblock
  Body: { reason?: string } (optional)
  Response: 200 OK | 404 Not Found
```

**Prior decisions:**
- shadcn/ui já instalado (13 componentes)
- Sonner para toasts
- React Hook Form + Zod para forms
- Admin auth via cookies httpOnly

### Task 2: Create Zod Validation Schema for Edit
**File:** `frontend/backoffice/src/lib/validation-schemas.ts`

1. Create `adminEditUserSchema` — partial fields (name, email, phone, address)
