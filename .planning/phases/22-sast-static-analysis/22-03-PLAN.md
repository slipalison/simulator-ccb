# Plan 22-03 — SAST Policy Enforcement, Branch Protection Rules, Alert Dashboard Setup

## Overview

Establish the governance layer around SAST: configure branch protection to block merges on unresolved ERROR findings, set up GitHub Security Tab dashboard for alert triage, document the false positive dismissal workflow, and establish a weekly review cadence for new alerts.

## Success Criteria

1. ✅ Branch `main` protection rule includes `SAST — Semgrep` and `SAST — CodeQL` as required status checks
2. ✅ GitHub Security Tab shows both Semgrep and CodeQL results with correct categories
3. ✅ Alert triage workflow documented: how to dismiss false positives, how to mark as fixed, how to track open findings
4. ✅ At least 1 false positive dismissed with documented reason (proves triage workflow works)
5. ✅ `.github/pull_request_template.md` includes SAST checklist item
6. ✅ Team knows how to run Semgrep locally (`semgrep scan --config auto --config .semrep/ .`)
7. ✅ No ERROR-level findings remain open without dismissal or fix (clean slate or documented backlog)

## Scope

### In Scope
- GitHub Branch Protection rules for `main` branch
- GitHub Security Tab dashboard review and alert triage
- False positive dismissal documentation
- PR template SAST checklist item
- Local SAST run instructions (documented in CONTRIBUTING.md or README)
- Initial alert triage (dismiss known FPs, document open findings)

### Out of Scope
- Custom CodeQL queries — not needed beyond built-in suites
- SAST integration with external dashboards (Jira, Slack) — future enhancement
- Automated alert notification rules — manual review cadence is sufficient for now
- SAST gating on non-main branches — only main is protected

## Technical Details

### Branch Protection Configuration

Navigate to **Settings > Branches > Branch protection rules > Edit `main`**:

1. Under **"Require status checks to pass before merging"**:
   - Search and add: `SAST — Semgrep`
   - Search and add: `SAST — CodeQL`
2. Check **"Require status checks to pass before merging"**
3. Check **"Require branches to be up to date before merging"**
4. Save

This blocks PR merges until both SAST jobs complete with success status.

### Alert Triage Workflow

GitHub Security Tab → Code scanning alerts:

1. **Open alert:** Shows file, line, description, severity, CWE, OWASP category
2. **Dismiss alert:** Click "Dismiss" → choose reason:
   - **False positive** — rule incorrectly flagged safe code
   - **Used in tests** — vulnerability is intentional for test code
   - **Won't fix** — accepted risk, documented justification
   - **Fixed** — vulnerability has been remediated
3. **Dismissal persists** across subsequent scans — dismissed alerts stay dismissed unless code changes reintroduce the issue

### PR Template Addition

Add to `.github/pull_request_template.md`:

```markdown
## Security Checklist

- [ ] SAST checks pass (Semgrep + CodeQL)
- [ ] No new `// nosem` suppressions added without justification
- [ ] No hardcoded credentials or tokens in this PR
- [ ] CSRF validation added for new POST/PUT/DELETE endpoints
```

### Local SAST Run Instructions

Document in `CONTRIBUTING.md` or project README:

```bash
# Semgrep (requires Python 3.8+)
pip install semgrep
semgrep scan --config auto --config .semgrep/ .

# CodeQL (requires GitHub CLI + CodeQL extension)
gh extension install github/gh-codeql
gh codeql database create test-db --language=csharp --command="dotnet build"
gh codeql database analyze test-db --format=sarifv2 --output=results.sarif
```

### ERROR vs WARNING Policy

| Severity | CI Behavior | Developer Action |
|----------|-------------|------------------|
| **ERROR** | Fails the job — blocks merge | Must fix OR dismiss as false positive |
| **WARNING** | Posts to Security Tab — does NOT block | Review and fix when convenient |
| **INFO** | Posts to Security Tab — does NOT block | Informational only |

Semgrep custom rules use ERROR for critical patterns (hardcoded creds, localStorage tokens, XSS) and WARNING for less critical ones (raw CPF/CNPJ comparison). CodeQL `security-extended` includes both ERROR and WARNING findings.

## Tasks

### Task 1: Run initial SAST scan and document all findings
**What:** Trigger CI (push to a branch or workflow_dispatch). Wait for both SAST jobs to complete. Open GitHub Security Tab → Code scanning alerts. Document every finding: rule ID, file, line, severity, whether it's a real issue or false positive.
**Test approach:** Create a spreadsheet or markdown table with columns: Tool, Rule ID, File, Line, Severity, Type (Real/FP), Status (Open/Fixed/Dismissed), Notes.
**Validation:** All findings documented. Real issues identified. False positives cataloged with reason for dismissal.

### Task 2: Dismiss known false positives with documented reasons
**What:** In GitHub Security Tab, dismiss each false positive with an appropriate reason. Add inline code comments explaining the dismissal (e.g., `// nosem: no-missing-csrf — this is a public webhook endpoint`).
**Test approach:** Dismiss at least 1 false positive. Verify it stays dismissed after a new scan. Check that dismissal reason is visible in the alert history.
**Validation:** At least 1 alert dismissed with documented reason. Dismissal persists after rescan.

### Task 3: Fix or create tickets for real security findings
**What:** For each real security issue found by SAST:
- If trivial to fix (e.g., remove hardcoded test credential, add `[ValidateAntiForgeryToken]`): fix immediately
- If non-trivial: create a GitHub Issue with severity, finding details, and remediation guidance
**Test approach:** Fix at least 1 trivial finding. Create at least 1 issue for non-trivial findings. Link issues to this phase.
**Validation:** Real findings addressed (fixed or ticketed). No ERROR-level issues left unaddressed without documentation.

### Task 4: Configure branch protection rules for SAST status checks
**What:** Add `SAST — Semgrep` and `SAST — CodeQL` to the `main` branch protection rule as required status checks.
**Test approach:**
- Go to Settings > Branches > Edit `main` rule
- Add both SAST jobs as required checks
- Create a draft PR and verify that SAST checks appear in the required checks list
- Verify merge button is disabled if SAST checks fail
**Validation:** Branch protection rule includes both SAST jobs. Draft PR shows SAST as required check. Merge blocked when SAST fails.

### Task 5: Add SAST checklist to `.github/pull_request_template.md`
**What:** If PR template exists, add SAST checklist section. If not, create `.github/pull_request_template.md` with: description, type of change, security checklist, testing notes.
**Test approach:** Create a draft PR and verify template renders. Check that SAST checklist items are present.
**Validation:** PR template includes: "SAST checks pass (Semgrep + CodeQL)", "No new `// nosem` suppressions without justification", "No hardcoded credentials", "CSRF validation for new endpoints".

### Task 6: Document local SAST run instructions
**What:** Add a section to `CONTRIBUTING.md` (or create it if it doesn't exist) with instructions for running Semgrep locally. Include: prerequisites (Python 3.8+), install command, scan command, how to interpret results, how to add `nosem` suppressions.
**Test approach:** Follow the documented instructions on a fresh terminal. Verify `pip install semgrep` succeeds. Verify `semgrep scan --config auto --config .semgrep/ .` produces results matching CI.
**Validation:** CONTRIBUTING.md (or equivalent) contains local SAST instructions. Instructions tested and working.

### Task 7: Verify end-to-end SAST policy enforcement
**What:** Simulate a security violation: introduce a deliberate ERROR-level finding (e.g., add `localStorage.setItem('token', 'fake')` to a test file). Push to a branch. Verify: (a) Semgrep job fails, (b) PR cannot be merged, (c) finding appears in Security Tab. Then revert the change and verify the job passes again.
**Test approach:**
1. Add `localStorage.setItem('authToken', 'test')` to a frontend file
2. Commit and push to a feature branch
3. Verify Semgrep job fails in CI
4. Verify PR merge is blocked
5. Verify finding in Security Tab
6. Revert the change
7. Verify Semgrep job passes
8. Verify finding is auto-closed as "Fixed"
**Validation:** Full cycle works: violation → CI failure → merge blocked → revert → CI pass → finding closed.

## Task Order

Sequential groups:
- **Group 1 (depends on Plans 22-01, 22-02):** Tasks 1, 2 (initial scan + dismiss FPs — needs SAST running)
- **Group 2 (depends on Task 1):** Task 3 (fix real findings — needs findings documented)
- **Group 3 (depends on Tasks 1-3):** Task 4 (branch protection — need to know SAST is working before gating)
- **Group 4 (parallel with Task 4):** Tasks 5, 6 (PR template + local docs — independent of branch protection)
- **Group 5 (depends on Tasks 3-6):** Task 7 (end-to-end validation — needs everything in place)

## Risk Assessment

| Risk | Probability | Impact | Mitigation |
|------|------------|--------|------------|
| Too many ERROR findings block all PRs | Medium | High | Baseline findings first (Task 1). Dismiss FPs (Task 2). Fix trivial issues (Task 3). Enable branch protection ONLY after clean baseline. |
| Branch protection requires historical check status | Low | Low | GitHub requires status checks to have run at least once on the branch before they can be added as required. Ensure SAST jobs ran on `main` at least once. |
| Dismissed alerts reappear on code change | Low | Low | GitHub tracks dismissed alerts by code fingerprint. If code changes, alert reopens — this is correct behavior. Document in triage workflow. |
| SAST adds merge friction | Medium | Medium | PR template checklist makes security visible. Weekly review cadence prevents alert backlog. Team training on SAST tools reduces confusion. |
