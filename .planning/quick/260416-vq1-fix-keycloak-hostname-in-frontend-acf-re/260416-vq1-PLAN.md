# Quick Task 260416-vq1: fix keycloak hostname in frontend ACF redirect — use localhost instead of docker internal hostname

## Problem

`KEYCLOAK_URL=http://keycloak:8080` (Docker-internal hostname) is used for both:
1. Server→Keycloak API calls (token exchange, refresh) — internal only, correct
2. Browser-facing redirects (authorization URL, logout URL) — must be publicly resolvable

The browser can't resolve `keycloak`, so `sendRedirect(event, authUrl, 302)` fails with
`Unsafe attempt to load URL http://keycloak:8080/...`

## Fix

Introduce `KEYCLOAK_PUBLIC_URL` (default: `http://localhost:8180`) for browser-facing URLs.
Keep `KEYCLOAK_URL` (default: `http://keycloak:8080`) for server-side calls only.

Note: Keycloak is exposed on host port 8180 (`ports: "127.0.0.1:8180:8080"` in compose.yaml),
and `KC_HOSTNAME: http://localhost:8180` is already set.

## Tasks

### Task 1 — Add KEYCLOAK_PUBLIC_URL to frontend/client/auth-server.ts

**Files:** `frontend/client/auth-server.ts`

**Action:**
- Add `const KEYCLOAK_PUBLIC_URL = process.env.KEYCLOAK_PUBLIC_URL || "http://localhost:8180";`
- Use `KEYCLOAK_PUBLIC_URL` in `buildAuthorizationUrl({ keycloakUrl: ... })` (line ~53)
- Use `KEYCLOAK_PUBLIC_URL` in the `logoutUrl` template literal (line ~147)
- Keep `KEYCLOAK_URL` for `exchangeCodeForTokens` and `refreshAccessToken`

**Verify:** grep shows `KEYCLOAK_PUBLIC_URL` in buildAuthorizationUrl and logoutUrl lines

### Task 2 — Add KEYCLOAK_PUBLIC_URL to frontend/backoffice/auth-server.ts

**Files:** `frontend/backoffice/auth-server.ts`

**Action:** Same as Task 1 — same pattern, same fix

**Verify:** grep shows `KEYCLOAK_PUBLIC_URL` in buildAuthorizationUrl and logoutUrl lines

### Task 3 — Set KEYCLOAK_PUBLIC_URL in compose.yaml for both frontend services

**Files:** `compose.yaml`

**Action:**
- In `frontend-client` environment: add `KEYCLOAK_PUBLIC_URL: http://localhost:8180`
- In `frontend-backoffice` environment: add `KEYCLOAK_PUBLIC_URL: http://localhost:8180`

**Verify:** compose.yaml contains KEYCLOAK_PUBLIC_URL for both services
