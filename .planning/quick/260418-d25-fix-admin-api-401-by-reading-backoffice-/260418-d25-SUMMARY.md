# Quick Task 260418-d25: Fix admin API 401 by reading backoffice_access_token cookie + remove ROPC legacy controller

## One-liner

`AdminSessionMiddleware` was looking for the legacy `adminRefreshToken` cookie (ROPC) instead of the `backoffice_access_token` cookie set by the Vinxi auth-server after Phase 33's Auth Code Flow + PKCE migration — every `/api/admin/*` request returned 401.

## Root Cause

Phase 33 migrated the backoffice frontend from ROPC (POST `/api/admin/auth/login`) to Auth Code Flow + PKCE handled by the Vinxi auth-server. The Vinxi server now exchanges the authorization code with Keycloak and writes two httpOnly cookies on `localhost:5174`:

```typescript
// frontend/backoffice/auth-server.ts:111-124
setCookie(event, "backoffice_access_token", tokens.accessToken, { httpOnly: true, ... });
setCookie(event, "backoffice_refresh_token", tokens.refreshToken, { httpOnly: true, ... });
```

The .NET `AdminSessionMiddleware`, however, was still scanning for the legacy ROPC cookie:

```csharp
private const string AdminCookieName = "adminRefreshToken";
...
if (!context.Request.Cookies.TryGetValue(AdminCookieName, out var refreshToken) || ...)
{
    await next();   // never sets Authorization header
    return;
}
```

Because the cookie was never present, the middleware always fell through, the `Authorization` header stayed empty, `UseAuthentication()` produced an unauthenticated principal, and `[Authorize(Roles = "admin")]` on `AdminUserController` rejected every request with 401.

## Fix

### Task 1 — Rewrite AdminSessionMiddleware (commit `fbbd76a`)

Simplified the middleware to a pure cookie-to-header converter. It now:

- Returns immediately for any path outside `/api/admin/*`.
- Reads the `backoffice_access_token` cookie. If absent, `next()` (downstream JwtBearer returns 401).
- If present, sets `context.Request.Headers.Authorization = "Bearer {accessToken}"` and `next()`.
- Does **not** call `IKeycloakTokenService` (the JWT is already valid from ACF — no exchange needed).
- Does **not** write response cookies (rotation is owned by the Vinxi `/auth/refresh` handler).
- Does **not** populate `HttpContext.Items["AdminEmail"]` (the JWT carries `email` natively; controllers already use `User.FindFirst("email")?.Value` because `Program.cs` sets `MapInboundClaims = false`).

The `/api/admin/auth/*` skip became unnecessary — the controller is removed in Task 2 and any future request to that path will get a 404 from MVC routing.

### Task 2 — Remove legacy ROPC controller and dead Application-layer code (commit `f771642`)

`AdminAuthController` is dead code after Phase 33 (`AdminLoginPage.tsx` now does `window.location.href = "/auth/login"` to the Vinxi route, not POST to `/api/admin/auth/login`; `admin-api.ts` no longer exports `loginAdmin`).

Confirmed via Grep that `AdminLoginCommand`, `AdminLoginCommandHandler`, `AdminLoginCommandValidator`, and `AdminSessionResponse` were consumed exclusively by the controller and its tests, then removed:

- Controller: `AdminAuthController.cs`
- Application: `AdminLoginCommand.cs`, `AdminLoginCommandHandler.cs`, `AdminLoginCommandValidator.cs`, `AdminSessionResponse.cs`
- Tests (full `tests/Onboarding.API.Tests/AdminAuth/` directory): `AdminAuthEndpointTests.cs`, `AdminAuthIntegrationTests.cs`, `AdminAuthIntegrationTestFactory.cs`, `AdminAuthTestFactory.cs`, `AdminLoginHandlerTests.cs`, `AdminLoginValidationTests.cs`
- DI: removed the two `AddScoped` lines for `AdminLoginCommand` handler/validator from `ApplicationServiceExtensions.AddApplication()`.

`IKeycloakTokenService` and `TokenResponse` are preserved — both still serve the **client** ROPC flow (`LoginCommand`, `RefreshTokenCommand`, `AuthController`).
