# Plan 22-02 — CodeQL Database Init, C# + JavaScript Queries, SARIF Export

## Overview

Integrate CodeQL into the CI pipeline for deep dataflow and taint analysis across both C# (.NET 10) and JavaScript/TypeScript (Vinxi) codebases. Configure security-extended and security-and-quality query suites, set up path exclusions for generated/test code, and upload results to GitHub Security Tab.

## Success Criteria

1. ✅ `.github/codeql/codeql-config.yml` exists with `security-extended` + `security-and-quality` query suites, path exclusions for test/build/generated code
2. ✅ `sast-codeql` job in `ci.yml` uses `github/codeql-action/init@v4`, `autobuild@v4`, `analyze@v4`
3. ✅ CodeQL analyzes both `csharp` and `javascript-typescript` languages
4. ✅ SARIF results uploaded with `category: codeql` to GitHub Security Tab
5. ✅ CodeQL scan completes without build errors on .NET 10 solution
6. ✅ CodeQL scan completes without errors on frontend projects (client + backoffice)
7. ✅ No `database finalize` exit code 32 error (confirms CodeQL 2.24.0+ .NET 10 support)

## Scope

### In Scope
- `.github/codeql/codeql-config.yml` — query suites, path exclusions, query filters
- `sast-codeql` job in `ci.yml` — init, autobuild, analyze steps
- SARIF upload via `github/codeql-action/analyze@v4` (built-in, no separate upload step needed)
- .NET 10 SDK setup for CodeQL autobuild
- Path exclusions: `**/node_modules/**`, `**/bin/**`, `**/obj/**`, `**/.vinxi/**`, `**/*.test.*`, `**/*.spec.*`, `**/Migrations/**`

### Out of Scope
- Semgrep — handled in Plan 22-01
- Branch protection rules — handled in Plan 22-03
- Custom CodeQL queries — use built-in suites only
- Scheduled weekly scans — nice-to-have, not required for R14.2
- CodeQL dashboard beyond GitHub Security Tab

## Technical Details

### CodeQL Config

```yaml
name: "Onboarding CodeQL Config"

queries:
  - uses: security-extended
  - uses: security-and-quality

query-filters:
  - exclude:
      problem.severity:
        - recommendation

paths-ignore:
  - "**/node_modules/**"
  - "**/bin/**"
  - "**/obj/**"
  - "**/.vinxi/**"
  - "**/*.test.*"
  - "**/*.spec.*"
  - "scripts/**"
  - "**/Migrations/**"
```

### CI Job

```yaml
sast-codeql:
  name: SAST — CodeQL
  runs-on: ubuntu-latest
  permissions:
    contents: read
    security-events: write
  steps:
    - uses: actions/checkout@v4

    - name: Setup .NET 10
      uses: actions/setup-dotnet@v4
      with:
        dotnet-version: "10.0.x"

    - name: Initialize CodeQL
      uses: github/codeql-action/init@v4
      with:
        languages: csharp, javascript-typescript
        config-file: .github/codeql/codeql-config.yml

    - name: Autobuild
      uses: github/codeql-action/autobuild@v4

    - name: Perform CodeQL Analysis
      uses: github/codeql-action/analyze@v4
      with:
        category: codeql
```

### Query Suites

| Suite | Description | Examples |
|-------|-------------|----------|
| `security-extended` | Broader security queries including lower-precision ones | SQL injection, XSS, path traversal, insecure deserialization, weak cryptography |
| `security-and-quality` | High-precision security + code quality queries | Unused variables, dead code, resource leaks, null dereference |

### Autobuild Behavior

`github/codeql-action/autobuild@v4` auto-detects the build system:
- **C#**: Runs `dotnet build` on the solution file
- **JavaScript/TypeScript**: No build step needed — CodeQL analyzes source directly

For this project, autobuild should work because:
- `Onboarding.slnx` is the only solution file at root
- `dotnet restore` + `dotnet build` should succeed (no external deps needed for analysis)
- Frontend projects don't require a build step for CodeQL JS/TS analysis

**Risk:** If autobuild fails, fallback to explicit `run: dotnet build Onboarding.slnx --configuration Release` step.

### SARIF Upload

`github/codeql-action/analyze@v4` automatically uploads SARIF to GitHub. No separate upload step needed. The `category: codeql` parameter distinguishes results from Semgrep findings.

### .NET 10 Compatibility

CodeQL 2.24.0+ (included in `github/codeql-action@v4`) supports .NET 10 and C# 14. The `database finalize` exit code 32 issue was resolved in 2.24.0 (Jan 2026). If it still occurs, fallback options:
1. Set `build-mode: none` in init step (analyzes without compilation — reduced precision)
2. Use explicit `dotnet build` before init to ensure compiled artifacts exist

## Tasks

### Task 1: Create `.github/codeql/codeql-config.yml`
**What:** Create CodeQL configuration with `security-extended` + `security-and-quality` query suites, exclude `recommendation` severity, set `paths-ignore` for test/build/generated directories.
**Test approach:** Validate YAML syntax. Verify both query suites listed. Verify paths-ignore patterns match actual project structure.
**Validation:** File exists at `.github/codeql/codeql-config.yml`. Contains both query suites. Paths-ignore excludes at least: node_modules, bin, obj, .vinxi, test files, Migrations.

### Task 2: Add `sast-codeql` job to `ci.yml`
**What:** Append the `sast-codeql` job to `.github/workflows/ci.yml`. Include: checkout, setup-dotnet@v4 (10.0.x), init@v4 (csharp + javascript-typescript), autobuild@v4, analyze@v4 with `category: codeql`. No `needs:` — runs in parallel.
**Test approach:** Validate YAML syntax. Verify `security-events: write` permission. Verify `languages: csharp, javascript-typescript`. Verify config-file points to `.github/codeql/codeql-config.yml`.
**Validation:** Job exists in ci.yml. No `needs:` key. All 5 steps present. Permissions and languages correct.

### Task 3: Verify CodeQL .NET 10 compatibility locally (dry run)
**What:** Before pushing, verify that CodeQL can analyze the .NET 10 project. Install CodeQL CLI locally (`gh extension install github/gh-codeql` + `gh codeql`) or push to a draft branch and check CI results.
**Test approach:** 
- Option A: Install CodeQL CLI locally, run `codeql database create test-db --language=csharp --command="dotnet build Onboarding.slnx"`.
- Option B: Push ci.yml changes to a feature branch, observe CodeQL job in GitHub Actions.
- If exit code 32 on `database finalize`, document the issue and apply workaround (`build-mode: none`).
**Validation:** CodeQL database creation succeeds OR workaround applied and documented.

### Task 4: Verify CodeQL JavaScript/TypeScript analysis
**What:** Verify CodeQL can analyze both frontend projects. Since JS/TS analysis doesn't require compilation, this should succeed automatically. Confirm by checking that `paths-ignore` correctly excludes `.vinxi/` and `node_modules/`.
**Test approach:** After CodeQL scan runs, verify SARIF includes JS/TS findings (not just C#). Check Security Tab for JavaScript-language alerts.
**Validation:** CodeQL scan includes JS/TS analysis step. Results cover both C# and JS/TS code.

### Task 5: Validate first scan results and document findings
**What:** After CodeQL runs (via CI), review findings in GitHub Security Tab. Document: (a) real security issues, (b) false positives, (c) query IDs that generate excessive noise.
**Test approach:** Push changes to a branch, wait for CI to complete. Open GitHub Security Tab → Code scanning alerts. Review each alert. Note query ID, file, severity.
**Validation:** Findings documented. False positives identified. If query generates excessive noise, document query ID for exclusion in Plan 22-03.

## Risk Assessment

| Risk | Probability | Impact | Mitigation |
|------|------------|--------|------------|
| CodeQL `database finalize` fails with .NET 10 | Low | High | CodeQL 2.24.0+ should support .NET 10. If it fails, use `build-mode: none` as workaround (reduced precision). |
| Autobuild fails on complex solution | Low | Medium | Fallback to explicit `dotnet build` step. Onboarding.slnx is simple — should work. |
| CodeQL consumes >7GB RAM on ubuntu-latest | Low | Medium | Project is small-to-medium. Should fit within 7GB. If not, use `ubuntu-latest-large`. |
| Excessive false positives from security-extended | Medium | Medium | First scan will baseline. Tune `query-filters.exclude` in config for noisy queries. |
| JavaScript analysis misses Vinxi-specific patterns | Medium | Low | CodeQL analyzes source JS/TS, not build output. Vinxi bundler transforms are invisible, but source-level analysis is still valuable. |
