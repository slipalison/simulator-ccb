## Critical Gaps (Blockers)

### P0-01: Password Reset Link Points to Wrong Port

**File:** `src/Onboarding.Application/Auth/Commands/ForgotPasswordCommand.cs` line 55

**Problem:** The reset password email contains a hardcoded link: `http://localhost:3001/reset-password?token=...`

**Impact:** Users who click the reset link land on a non-existent server. The frontend runs on port **5173**, not 3001.

**Fix Required:**
- Add `Frontend:BaseUrl` configuration (e.g., from environment variable)
- Use configured URL instead of hardcoded value
- Or use relative path if sending from same origin

**Estimated effort:** ~10 minutes

---

### P0-02: No E2E Test Coverage

**Problem:** `tests/ui-ux-validation.spec.ts` exists but `@playwright/test` is not installed. Zero automated E2E tests.

**Impact:** Critical user flows (registration → login → profile, forgot/reset password) have no automated verification. Only manual testing.

**Fix Required:**
- Install `@playwright/test`
- Convert existing spec file to working Playwright tests
- Or remove the file if E2E testing is deferred

**Estimated effort:** 1-2 hours for basic coverage

## Moderate Issues

### P1-01: Cookie Secure Flag Not Environment-Configured

**File:** `src/Onboarding.API/Controllers/AuthController.cs` — `Secure = false` hardcoded on all cookie options.

**Impact:** In production (HTTPS), cookies should have `Secure = true`. Currently they would work but not enforce HTTPS-only transmission.

**Fix Required:** Read from configuration (`Cookie:Secure` or infer from `ASPNETCORE_ENVIRONMENT`).

### P1-02: Orphan File — frontend/src/client.tsx

**Problem:** File exists but is never imported. `index.html` correctly loads `main.tsx`.

**Impact:** Dead code, confusion for developers.

**Fix Required:** Delete the file.
