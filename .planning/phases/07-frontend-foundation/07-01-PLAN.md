ATENCAO: Esta tarefa existe explicitamente porque planos anteriores listaram o Dockerfile
em `files_modified` mas nao incluiram instrucoes de atualizacao — esse foi o bloqueio
reportado pelo checker. O Dockerfile DEVE ser atualizado aqui com instrucoes explicitas.

Substituir o conteudo de `frontend/Dockerfile` por:

```dockerfile
FROM node:22-alpine AS dev
WORKDIR /app

# Copiar arquivos de dependencias para cache de camadas
COPY package.json package-lock.json* ./
RUN npm install

# Copiar fontes (bind mount do compose.yaml sobrescreve em dev)
COPY . .

EXPOSE 5173

# vinext dev --port 5173 em vez de vinxi dev
# A porta padrao do vinext e 3001; --port 5173 e obrigatorio para compose.yaml
CMD ["npx", "vinext", "dev", "--port", "5173"]
```

Por que usar `npx vinext` em vez de `npm run dev`:
- Garante que o comando vinext seja invocado diretamente
- O script `dev` no package.json usa `vinext dev --port 5173` — ambas as formas funcionam
- Usar `npx vinext` e mais explicito e evita dependencia de PATH dentro do container

Alternativa equivalente (se preferir usar npm scripts):
```dockerfile
CMD ["npm", "run", "dev"]
```
onde `package.json` scripts.dev = `"vinext dev --port 5173"`.

Escolher `CMD ["npm", "run", "dev"]` para consistencia com o padrao existente no projeto.
O arquivo final deve ser:

```dockerfile
FROM node:22-alpine AS dev
WORKDIR /app

# Copiar arquivos de dependencias para cache de camadas
COPY package.json package-lock.json* ./
RUN npm install

# Copiar fontes (bind mount do compose.yaml sobrescreve em dev)
COPY . .

EXPOSE 5173

# vinext dev --port 5173 (package.json scripts.dev)
# Nota: porta padrao do vinext e 3001; --port 5173 e obrigatorio para compose.yaml
CMD ["npm", "run", "dev"]
```

Verificar que o compose.yaml nao precisa de alteracoes — o servico frontend ja tem:

- `build: context: ./frontend, dockerfile: Dockerfile` (correto)
- A variavel de ambiente `PORT` nao e necessaria porque o flag `--port 5173` e passado diretamente

Se o compose.yaml tiver `command:` hardcoded com `vinxi`, atualizar para remover (o Dockerfile CMD e suficiente).
