    **2. Extend RegisterEmployeeCommandHandler** (D-16):

    After creating the Keycloak user AND seeding the employee's AccessGroup, add the user to the corresponding Keycloak group:

    ```csharp
    // After user creation and DB save, add employee to Keycloak group (D-16)
    var targetRealm = "client";
    var accessGroup = await _accessGroupRepository.GetByIdAsync(employee.AccessGroupId, ct);

    if (accessGroup is not null)
    {
        var keycloakGroupId = await _keycloakUserService.GetGroupByNameAsync(targetRealm, accessGroup.Name, ct);
        if (keycloakGroupId is not null)
        {
            await _keycloakUserService.AddUserToGroupAsync(targetRealm, keycloakUserId, keycloakGroupId, ct);
        }
        else
        {
            _logger.LogWarning("Keycloak group '{GroupName}' not found for employee {EmployeeId}. Employee created but not added to Keycloak group.", accessGroup.Name, employee.Id);
        }
    }
    ```

    This applies to the default `viewer` group as well as any explicitly specified AccessGroupId.

    **3. Extend ChangeEmployeeAccessGroupCommandHandler** (D-15):

    After changing the employee's AccessGroupId in the DB, sync the Keycloak group membership:
    ```csharp
    // After changing AccessGroupId in DB, sync Keycloak group (D-15)
    var targetRealm = "client";

    // Resolve new group
    var newGroup = await _accessGroupRepository.GetByIdAsync(command.NewAccessGroupId, ct)
        ?? throw new KeyNotFoundException($"Access group with ID {command.NewAccessGroupId} not found.");

    var newKeycloakGroupId = await _keycloakUserService.GetGroupByNameAsync(targetRealm, newGroup.Name, ct);
    if (newKeycloakGroupId is not null)
    {
        await _keycloakUserService.AddUserToGroupAsync(targetRealm, employee.KeycloakUserId, newKeycloakGroupId, ct);
    }

    // Remove from old group
    var previousGroup = await _accessGroupRepository.GetByIdAsync(employee.AccessGroupId, ct);
    if (previousGroup is not null)
    {
        var oldKeycloakGroupId = await _keycloakUserService.GetGroupByNameAsync(targetRealm, previousGroup.Name, ct);
        if (oldKeycloakGroupId is not null)
        {
            await _keycloakUserService.RemoveUserFromGroupAsync(targetRealm, employee.KeycloakUserId, oldKeycloakGroupId, ct);
        }
    }

    // Best-effort sync: failures logged but not rethrown (D-15 eventual consistency)
    ```

    Wrap the group sync in a try-catch that logs warnings but does NOT rethrow — eventual consistency pattern per D-15. The DB update is the source of truth; Keycloak sync is best-effort.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → API | JWT Bearer token issued by client realm Keycloak |
| API → Authorization Policy | Policy checks permissions resolved by middleware from DB |
| API → Keycloak Admin API | Group sync calls (CreateGroup, AddUser, RemoveUser) |
| DB → Keycloak | DB is source of truth; Keycloak sync is eventual consistency |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-39-11 | E (Elevation) | Permission policy enforcement | mitigate | Policies checked per-endpoint. Viewer cannot POST/PUT/DELETE — only GET. EmployeeWrite prevents viewers from writing. |
| T-39-12 | E (Elevation) | AccessGroupsManage policy | mitigate | Only admin-empresa and PJ owner can change groups (PERM-04). Viewer and dashboard lack this permission. |
| T-39-13 | D (Denial) | Keycloak group sync failure | mitigate | Best-effort with logging. DB is source of truth — Keycloak group membership failure is logged but doesn't block the operation (D-15 eventual consistency) |
| T-39-14 | S (Spoofing) | CompanyId check | mitigate | All endpoints still verify companyId != _currentCompanyService.CompanyId → 403 (D-18). Even if policy allows, wrong company gets 403. |
| T-39-15 | T (Tampering) | Cross-company data access | mitigate | HasQueryFilter + controller check + service-layer check = defense-in-depth (D-17, D-18, D-19). Three layers of isolation. |
</threat_model>
