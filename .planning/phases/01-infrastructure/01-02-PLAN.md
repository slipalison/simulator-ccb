  "ssoSessionMaxLifespan": 28800,
  "ssoSessionIdleTimeout": 1800,

**Critical notes:**
- `sslRequired: "external"` means HTTPS is required for non-loopback requests but HTTP is
  allowed from localhost — correct for dev.
- `standardFlowEnabled: false` on both clients — neither needs Authorization Code flow in v1.
- `redirectUris: ["http://localhost:5173/*"]` on onboarding-app — the `*` wildcard here is
  acceptable because this is a public (no-secret) client used for ROPC; there is no
  authorization code redirect in this flow. Phase 2 (hardening) will tighten this.
- `clientScopeMappings` is the correct field to assign realm-management roles to the service
  account. This is confirmed across multiple Keycloak community sources for the import format.
  If Keycloak startup logs show the role was not applied, the fallback is to configure via
  Admin Console and re-export — see RESEARCH.md Open Question 1.

Start only the database and Keycloak services (not api/frontend — their Dockerfiles don't
exist yet). Verify Keycloak becomes healthy and the realm was imported.

Run these commands in sequence:

```bash
# Start only the infrastructure services (api and frontend Dockerfiles don't exist yet)
docker compose up app_db keycloak_db keycloak -d --wait

# Wait for healthchecks — this can take 60-90 seconds
docker compose ps

# Verify Keycloak is healthy
docker compose ps keycloak | grep "(healthy)"

# Verify realm exists via Admin API (use bootstrap credentials from .env)
curl -s -X POST "http://localhost:8180/realms/master/protocol/openid-connect/token" \
  -d "client_id=admin-cli&grant_type=password&username=admin&password=Admin@Keycloak2026!" \
  | python3 -c "import json,sys; t=json.load(sys.stdin); print('Token obtained:', 'access_token' in t)"

# Get realm list (store token from above step first, or inline it)
# Simpler verification: check realm endpoint returns 200
ADMIN_TOKEN=$(curl -s -X POST "http://localhost:8180/realms/master/protocol/openid-connect/token" \
  -d "client_id=admin-cli&grant_type=password&username=admin&password=Admin@Keycloak2026!" \
  | python3 -c "import json,sys; print(json.load(sys.stdin)['access_token'])")

curl -s -o /dev/null -w "%{http_code}" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  "http://localhost:8180/admin/realms/onboarding"
# Expected: 200
```

If realm returns 200, it was imported successfully.

If the service account role binding needs to be verified:
```bash
# List service account for onboarding-api-admin and check its roles
curl -s -H "Authorization: Bearer $ADMIN_TOKEN" \
  "http://localhost:8180/admin/realms/onboarding/clients?clientId=onboarding-api-admin" \
  | python3 -c "import json,sys; clients=json.load(sys.stdin); print('Client ID:', clients[0]['id'] if clients else 'NOT FOUND')"
```

After verification, tear down to clean state for Plan 03:
```bash
docker compose down
```
(Do NOT use `down -v` — that destroys volumes. A plain `down` stops containers but keeps
Keycloak's imported realm in the volume. Future `docker compose up` will skip re-import
because realm already exists, which is correct and expected.)
