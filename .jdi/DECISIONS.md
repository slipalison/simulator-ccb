D-16 (2026-05-16, Phase 49 reabertura): Workflow de dev local e EXCLUSIVAMENTE `docker compose up`. Proibido rodar `pnpm dev`/`npm run dev` diretamente no Windows host nos diretorios `frontend/client` ou `frontend/backoffice` — cria processo vinxi-host stale que ouve em `[::]:5173`/`:5174` (IPv6) e intercepta requests resolvidos via `localhost`, com fetch upstream para `api:8080` falhando porque host Windows nao acessa a bridge Docker `onboarding-net`. D-17 (2026-05-16, Phase 49 reabertura): Playwright configs e quaisquer scripts de teste que disparam fetch contra o stack local DEVEM usar `http://127.0.0.1:PORT`, nunca `http://localhost:PORT`. Elimina ambiguidade IPv6/IPv4 do resolver Windows e garante roteamento para o port mapping do Docker. Aplica-se a `frontend/client/playwright.config.ts`, `frontend/client/pw-no-setup.config.ts`, `frontend/backoffice/playwright.config.ts` e todo spec novo que mencione baseURL.

Refined 2026-05-16 (iter 3): D-17 aplica-se APENAS a `api-proxy.spec.ts` (probes diretos que nao atravessam Keycloak). Auth-flow specs (`auth-flow.spec.ts`, `admin-auth-flow.spec.ts`) ficam em `localhost` para alinhar com os `redirectUris`/`webOrigins` dos realm JSONs do Keycloak que somente contém variantes `localhost`. Usar `127.0.0.1` nos auth-flow specs causava "Invalid state" porque o cookie `pkce_state` era setado na origem `127.0.0.1` mas o Keycloak redirecionava o callback para `localhost`, e o browser nao enviava o cookie cross-origin. Cada project block no Playwright config sobreescreve `baseURL` adequadamente: api-proxy herda `127.0.0.1` do `use` global; auth-flow project blocks definem `baseURL: http://localhost:PORT` explicitamente.

D-18 (2026-05-17, Phase 50): REL-09 (uma única associação ATIVA por par Fundo-Cedente) é enforced em DUAS camadas — partial unique index Postgres `(FundoId, CedenteId) WHERE Status='ATIVO'` + invariante de domínio no aggregate `FundoCedente`. DB é o gate autoritativo contra race condition sob concurrent POST; o domínio lança `DuplicateActiveAssociationException` tipada no fluxo feliz, e o race exception do DB é traduzido para HTTP 409 pelo GlobalExceptionHandler. Defesa em profundidade.

D-19 (2026-05-17, Phase 50): Status da associação é coluna explícita com enum `ATIVO`/`INATIVO`/`HISTORICO`, NÃO derivado da janela de datas. Janela de datas declara vigência; Status registra estado lógico atual. REL-09 partial index usa `WHERE Status='ATIVO'` literal (sem cálculo temporal). Domain pode flagar drift se Status='ATIVO' mas `data_fim < NOW()` em operações de status transition, mas não bloqueia consistência entre os dois campos automaticamente.
