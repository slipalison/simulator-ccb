# Plan 24-01 — Trivy Image Scanning + Multi-Image CI Pipeline + SARIF Report

## Overview

Add Trivy container image scanning to the CI pipeline. After Docker images are built, Trivy scans them for known CVEs in OS packages and application dependencies. Results uploaded to GitHub Security Tab via SARIF. Scan fails on CRITICAL or HIGH vulnerabilities.

## Success Criteria

1. ✅ `container-scan-trivy` job in `ci.yml` builds backend Docker image and runs `trivy image` scan
2. ✅ SARIF results uploaded via `github/codeql-action/upload-sarif@v4` with `category: trivy-image`
3. ✅ Scan fails if CRITICAL or HIGH CVEs found in image
4. ✅ `--ignore-unfixed: true` prevents failures on unpatched CVEs
5. ✅ Trivy uses `aquasecurity/trivy-action@master` with `scan-type: image`
6. ✅ Image built in CI step before scanning — no external image dependency

## Scope

### In Scope
- `container-scan-trivy` job in `.github/workflows/ci.yml`
- Docker build step for backend API image (uses existing Dockerfile or inline build)
- Trivy image scan with CRITICAL,HIGH severity filter
- SARIF upload to GitHub Security Tab

### Out of Scope
- Frontend container scanning — frontend projects use Vinxi (Node.js server), not Dockerfiles in this phase
- Keycloak image scanning — managed by upstream, not our responsibility
- Dockle container linting — handled in Plan 24-02
- Multi-stage build optimization — not required for scanning

## Technical Details

### Docker Build for Backend

The project may or may not have a Dockerfile for the backend API. If it exists, use it. If not, the CI job should:
1. Create a temporary Dockerfile for the backend API
2. Build the image
3. Scan with Trivy
4. Clean up (image is not pushed)

### CI Job

```yaml
container-scan-trivy:
  name: Container Scan — Trivy Image
  runs-on: ubuntu-latest
  permissions:
    contents: read
    security-events: write
  steps:
    - uses: actions/checkout@v4

    - name: Build backend Docker image
      run: |
        if [ -f Dockerfile ]; then
          docker build -t onboarding-api:ci .
        elif [ -f src/Onboarding.API/Dockerfile ]; then
          docker build -t onboarding-api:ci -f src/Onboarding.API/Dockerfile .
        else
          echo "No Dockerfile found — skipping container scan"
          exit 0
        fi

    - name: Run Trivy image scan
      uses: aquasecurity/trivy-action@master
      if: hashFiles('Dockerfile', 'src/Onboarding.API/Dockerfile') != ''
      with:
        image-ref: onboarding-api:ci
        format: sarif
        output: trivy-image-results.sarif
        severity: CRITICAL,HIGH
        exit-code: "1"
        ignore-unfixed: true

    - name: Upload Trivy Image SARIF
      uses: github/codeql-action/upload-sarif@v4
      if: always()
      with:
        sarif_file: trivy-image-results.sarif
        category: trivy-image
```

### Difference from Plan 23-02 (Trivy fs)

| Aspect | Plan 23-02 (Trivy fs) | Plan 24-01 (Trivy image) |
|--------|----------------------|--------------------------|
| Scan type | Filesystem (`fs`) | Image (`image`) |
| Target | package-lock.json, *.csproj | Built Docker image layers |
| Detects | Dependency CVEs | OS package CVEs + app deps |
| Requires build | No | Yes (Docker image build) |
| Category in SARIF | `trivy` | `trivy-image` |

## Tasks

### Task 1: Check for existing Dockerfile
**What:** Search project root for `Dockerfile` or `*.Dockerfile` files. Check `src/Onboarding.API/`, root directory, and `infra/` directory.
**Test approach:** `find . -name 'Dockerfile' -o -name '*.Dockerfile'`
**Validation:** If Dockerfile exists, note its path. If not, this job should skip gracefully.

### Task 2: Add `container-scan-trivy` job to `ci.yml`
**What:** Append the job to `.github/workflows/ci.yml`. Conditional Docker build — skips if no Dockerfile found. Trivy image scan with SARIF upload.
**Test approach:** Validate YAML syntax. Verify conditional `if` on hashFiles for Dockerfile detection. Verify SARIF upload with `category: trivy-image`.
**Validation:** Job exists in ci.yml. Conditional skip works when no Dockerfile. All steps present when Dockerfile exists.

### Task 3: Validate Trivy image scan (if Dockerfile exists)
**What:** If Dockerfile exists, test the build + scan locally or in CI. Verify Trivy can analyze the built image and produce SARIF output.
**Test approach:** `docker build -t onboarding-api:ci -f <Dockerfile> .` then `trivy image --severity CRITICAL,HIGH --ignore-unfixed onboarding-api:ci`
**Validation:** Image builds successfully. Trivy scan completes. SARIF output generated.

## Task Order

Sequential:
- **Task 1:** Check for Dockerfile
- **Task 2:** Add job to ci.yml (depends on Task 1 — need to know Dockerfile path)
- **Task 3:** Validate scan (depends on Task 2, only if Dockerfile exists)
