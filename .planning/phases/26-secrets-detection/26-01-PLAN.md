# Plan 26-01 — Gitleaks Pre-Commit + CI + Custom Rules + Allowlist Configuration

## Overview

Integrate Gitleaks into the CI pipeline for secrets detection. Gitleaks scans the entire git history and current codebase for hardcoded credentials, API keys, tokens, and other secrets. Custom rules target project-specific secret patterns (Keycloak secrets, database connection strings, JWT keys).

## Success Criteria

1. ✅ `.gitleaks.toml` configured with custom rules for: AWS/Azure/GCP keys, JWT signing keys, DB connection strings, Keycloak secrets, API keys
2. ✅ `secrets-gitleaks` job in `ci.yml` runs `gitleaks detect` on the full git history
3. ✅ Scan fails if ANY secret is detected (no allowlist for real secrets)
4. ✅ `gitleaks-report.json` generated for review
5. ✅ Gitleaks uses `gitleaks/gitleaks-action@v2` (official action)
6. ✅ Local pre-commit hook available for development

## Scope

### In Scope
- `.gitleaks.toml` — custom secret detection rules
- `.gitleaksignore` — allowlist for known false positives (test fixtures, documentation examples)
- `secrets-gitleaks` job in `.github/workflows/ci.yml`
- Pre-commit hook documentation in CONTRIBUTING.md
- Git history scanning (full repo, not just current commit)

### Out of Scope
- TruffleHog verification — handled in Plan 26-02
- Pre-commit hook auto-install — documented, not enforced
- Secret rotation automation — manual process
- Pre-receive hooks — GitHub-side enforcement (future)

## Technical Details

### Custom Gitleaks Rules

```toml
# .gitleaks.toml
title = "Onboarding Secrets Detection"

[extend]
useDefault = true  # Include built-in rules

[[rules]]
id = "keycloak-admin-client-secret"
description = "Keycloak admin client secret"
regex = '''client_secret\s*=\s*["'][a-zA-Z0-9\-_]{20,}["']'''
tags = ["keycloak", "secret"]

[[rules]]
id = "connection-string-password"
description = "Database connection string with password"
regex = '''Host=[^;]+;\s*Password\s*=\s*[^\s;]+'''
tags = ["database", "secret"]

[[rules]]
id = "jwt-signing-key"
description = "JWT signing key or secret"
regex = '''(?:jwt|signing)[_-]?(?:key|secret)\s*=\s*["'][a-zA-Z0-9\-_]{16,}["']'''
tags = ["jwt", "secret"]

[[rules]]
id = "keycloak-realm-url"
description = "Keycloak realm URL with embedded credentials"
regex = '''https?://[^:]+:[^@]+@keycloak'''
tags = ["keycloak", "url-credentials"]
```

### CI Job

```yaml
secrets-gitleaks:
  name: Secrets — Gitleaks
  runs-on: ubuntu-latest
  permissions:
    contents: read
    security-events: write
  steps:
    - uses: actions/checkout@v4
      with:
        fetch-depth: 0  # Full git history for scanning

    - name: Run Gitleaks
      uses: gitleaks/gitleaks-action@v2
      env:
        GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
      with:
        config-path: .gitleaks.toml
        report-path: gitleaks-report.json
        verbose: true
```

### `.gitleaksignore`

False positives from test fixtures or documentation should be allowed here:

```
# Test fixture secrets (intentional, not real)
# Format: fingerprint
abc123def456  # Test fixture: mock Keycloak secret
```

### Pre-Commit Hook

Add to CONTRIBUTING.md:

```bash
# Install gitleaks
brew install gitleaks  # macOS
# or
sudo snap install gitleaks  # Linux

# Run before commit
gitleaks detect --source . --config .gitleaks.toml
```

## Tasks

### Task 1: Create `.gitleaks.toml`
**What:** Create custom Gitleaks configuration extending default rules with project-specific patterns (Keycloak, DB connection strings, JWT keys).
**Test approach:** Run `gitleaks detect --config .gitleaks.toml --source .` locally. Verify no false positives on current codebase. Test with intentional secret to confirm detection.
**Validation:** File exists at `.gitleaks.toml`. Extends default rules. Custom rules for Keycloak, DB, JWT present.

### Task 2: Create `.gitleaksignore`
**What:** Create allowlist for known false positives (test fixtures, documentation examples). Empty initially — only add when false positives are confirmed.
**Test approach:** File exists, empty or with documented exceptions.
**Validation:** `.gitleaksignore` at project root. Comments explain any allowed fingerprints.

### Task 3: Add `secrets-gitleaks` job to `ci.yml`
**What:** Append the job to `.github/workflows/ci.yml`. Uses `gitleaks/gitleaks-action@v2`. Full git history fetch (`fetch-depth: 0`). SARIF upload.
**Test approach:** Validate YAML syntax. Verify `fetch-depth: 0` for full history scan. Verify `config-path: .gitleaks.toml`.
**Validation:** Job exists in ci.yml. Permissions correct. Full history scanning enabled.

### Task 4: Document pre-commit hook in CONTRIBUTING.md
**What:** Add section to CONTRIBUTING.md with Gitleaks installation and local run instructions.
**Test approach:** Instructions clear and tested on fresh environment.
**Validation:** CONTRIBUTING.md contains pre-commit section with install commands and local scan instructions.
