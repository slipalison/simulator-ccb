# Plan 25-01 — Checkov Docker Compose Scanning + Policy Configuration + SARIF Export

## Overview

Integrate Checkov into the CI pipeline for Infrastructure as Code (IaC) scanning. Checkov analyzes `compose.yaml` and Dockerfile for security misconfigurations: privileged containers, exposed secrets, missing resource limits, running as root, etc. Results uploaded to GitHub Security Tab via SARIF.

## Success Criteria

1. ✅ `iac-checkov` job in `ci.yml` runs `checkov --framework dockerfile_compose --file compose.yaml`
2. ✅ SARIF results uploaded via `github/codeql-action/upload-sarif@v4` with `category: checkov`
3. ✅ Scan fails on CRITICAL or HIGH severity checks
4. ✅ `compose.yaml` passes all critical checks (no privileged mode, no secrets in env, proper healthchecks)
5. ✅ Checkov installed via `bridgecrew/checkov-action@master` (official GitHub Action)

## Scope

### In Scope
- `iac-checkov` job in `.github/workflows/ci.yml`
- Checkov scanning of `compose.yaml` and Dockerfile
- SARIF upload to GitHub Security Tab
- `.checkov.yml` configuration file (optional suppressions)

### Out of Scope
- Kubernetes scanning — no K8s manifests yet, Kubescape handles Phase 25-02
- Terraform scanning — not used in this project
- Helm chart scanning — not applicable
- Cloud infrastructure scanning — no AWS/GCP/Azure resources

## Technical Details

### CI Job

```yaml
iac-checkov:
  name: IaC — Checkov
  runs-on: ubuntu-latest
  permissions:
    contents: read
    security-events: write
  steps:
    - uses: actions/checkout@v4

    - name: Run Checkov IaC scan
      uses: bridgecrew/checkov-action@master
      with:
        file: compose.yaml
        framework: dockerfile_compose
        output: cli,sarif
        output-file-path: checkov-results.sarif
        soft-fail: false
        check: CKV_DOCKER_*,CKV2_DOCKER_*

    - name: Upload Checkov SARIF
      uses: github/codeql-action/upload-sarif@v4
      if: always()
      with:
        sarif_file: checkov-results.sarif
        category: checkov
```

### Key Checkov Checks for Docker Compose

| Check ID | Description | Severity |
|----------|-------------|----------|
| CKV_DOCKER_1 | Container not running as root | MEDIUM |
| CKV_DOCKER_2 | HEALTHCHECK instruction present | LOW |
| CKV_DOCKER_3 | No `privileged: true` | CRITICAL |
| CKV_DOCKER_4 | No `--cap-add ALL` | HIGH |
| CKV_DOCKER_5 | No secrets in environment variables | HIGH |
| CKV_DOCKER_6 | Memory limits configured | MEDIUM |
| CKV_DOCKER_7 | CPU limits configured | MEDIUM |
| CKV_DOCKER_8 | No `network_mode: host` | HIGH |

### `.checkov.yml` Configuration

```yaml
# Checkov configuration for IaC scanning
soft-fail: false
compact: true
framework:
  - dockerfile_compose
check:
  - CKV_DOCKER_*
  - CKV2_DOCKER_*
```

### Known Issues

The `compose.yaml` uses environment variables for database passwords (`${APP_DB_PASSWORD}`). Checkov may flag this as "secrets in environment variables" — but these are managed via `.env` file (not committed). This is a false positive that can be suppressed with a comment or `.checkov.yml` skip.

## Tasks

### Task 1: Create `.checkov.yml`
**What:** Create Checkov configuration with dockerfile_compose framework, compact output, soft-fail disabled.
**Test approach:** Validate YAML syntax. Verify framework list.
**Validation:** File exists at `.checkov.yml`. Contains correct framework and settings.

### Task 2: Add `iac-checkov` job to `ci.yml`
**What:** Append the job to `.github/workflows/ci.yml`. Uses `bridgecrew/checkov-action@master`. Scans compose.yaml and Dockerfile. SARIF upload.
**Test approach:** Validate YAML syntax. Verify `security-events: write` permission. Verify `framework: dockerfile_compose`. Verify SARIF upload with `category: checkov`.
**Validation:** Job exists in ci.yml. All steps present. Permissions correct.

### Task 3: Test Checkov scan locally
**What:** Run Checkov locally against compose.yaml to identify current findings.
**Test approach:** `docker run --rm -v $(pwd):/checkov bridgecrew/checkov --framework dockerfile_compose --file compose.yaml --compact`
**Validation:** Scan completes. Findings documented. Any CRITICAL/HIGH findings either fixed or suppressed with justification.

## Task Order
