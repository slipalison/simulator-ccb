<task type="auto">
  <name>Task 1: Create Zod validation schemas for PF and PJ</name>
  <files>frontend/src/lib/validation-schemas.ts</files>
  <action>
    Create a shared validation schemas file with two Zod schemas that mirror the server-side FluentValidation rules.
    
    pfRegistrationSchema:
    - nome: string().min(1, "Nome é obrigatório").min(2, "Nome deve ter pelo menos 2 caracteres")
    - cpf: string()
      .min(1, "CPF é obrigatório")
      .regex(/^\d{11}$/, "CPF deve conter 11 dígitos")
      .refine(/* CPF check-digit validation — implement modulo 11 algorithm */)
      → Error message: "CPF inválido"
    - email: string().min(1, "Email é obrigatório").email("Email inválido")
    - phone: string()
      .min(1, "Telefone é obrigatório")
      .regex(/^\+?\d{10,11}$/, "Telefone deve conter 10 ou 11 dígitos")
    - password: string()
      .min(8, "Senha deve ter pelo menos 8 caracteres")
      .regex(/[A-Z]/, "Senha deve conter pelo menos uma letra maiúscula")
      .regex(/[a-z]/, "Senha deve conter pelo menos uma letra minúscula")
      .regex(/\d/, "Senha deve conter pelo menos um número")
      .regex(/[!@#$%^&*()_+\-=\[\]{};':"\\|,.<>\/?]/, "Senha deve conter pelo menos um caractere especial")
    
    pjRegistrationSchema:
    - razaoSocial: string().min(1, "Razão Social é obrigatória").min(2, "Razão Social deve ter pelo menos 2 caracteres")
    - cnpj: string()
      .min(1, "CNPJ é obrigatório")
      .regex(/^\d{14}$/, "CNPJ deve conter 14 dígitos")
      .refine(/* CNPJ check-digit validation — implement modulo 11 algorithm for CNPJ */)
      → Error message: "CNPJ inválido"
    - email, phone, password: same rules as PF
    
    Export: `export const pfRegistrationSchema` and `export const pjRegistrationSchema`
    Export inferred types: `export type PfRegistrationData = z.infer<typeof pfRegistrationSchema>`
    
    What to avoid:
    - Don't use external CPF/CNPJ validation libraries — implement inline (keeps bundle small)
    - Don't skip password validation — must mirror Keycloak password policy (SEC-02)
    - CPF/CNPJ regex accepts digits only (no dots/dashes) — form should strip non-digits on blur
  </action>
  <verify>
    1. npx tsc --noEmit passes
    2. Test manually: pfRegistrationSchema.parse({ nome: "Jo", cpf: "12345678901", email: "test@test.com", phone: "11999999999", password: "Test@1234" }) succeeds
    3. Test manually: pfRegistrationSchema.safeParse({ cpf: "123" }).success === false
  </verify>
  <done>Both schemas validate correct data and reject invalid CPF/CNPJ, missing fields, weak passwords</done>
</task>
