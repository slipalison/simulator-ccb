Substituir `frontend/app.config.ts` completo pelo seguinte conteúdo:

```typescript
import { createApp } from "vinxi";
import react from "@vitejs/plugin-react";
import tailwindcss from "@tailwindcss/vite";
import { fileURLToPath, URL } from "node:url";

export default createApp({
  routers: [
    {
      name: "public",
      type: "static",
      dir: "./public",
    },
    {
      name: "client",
      type: "spa",
      handler: "./index.html",
      vite: {
        server: {
          host: "0.0.0.0",
          port: 5173,
          hmr: { host: "localhost", port: 5173, clientPort: 5173 },
          watch: { usePolling: true, interval: 1000 },
        },
        resolve: {
          alias: {
            "@": fileURLToPath(new URL("./src", import.meta.url)),
          },
        },
      },
      plugins: () => [react(), tailwindcss()],
    },
  ],
});
```

NOTAS CRÍTICAS (pesquisa Pitfall 2 e 3):
- `plugins: () => [react(), tailwindcss()]` DEVE estar dentro do router SPA — NÃO em um
  vite.config.ts separado. Um vite.config.ts paralelo causa conflito com o Vinxi.
- O alias `@/*` precisa estar em DOIS lugares: (1) `vite.resolve.alias` no app.config.ts
  E (2) `paths` no tsconfig.json. Sem ambos, imports com @/ falham em runtime ou no TS.

Substituir `frontend/tsconfig.json` completo:

```json
{
  "compilerOptions": {
    "target": "ES2020",
    "lib": ["ES2020", "DOM", "DOM.Iterable"],
    "jsx": "react-jsx",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true,
    "skipLibCheck": true,
    "baseUrl": ".",
    "paths": {
      "@/*": ["./src/*"]
    }
  },
  "include": ["src", "app.config.ts", "vitest.config.ts"]
}
```

Verificar que o TypeScript não reclama do config:

### Passo 1 — Criar globals.css com Tailwind v4 e variáveis shadcn/ui

Criar `frontend/src/globals.css`:

```css
@import "tailwindcss";

@layer base {
  :root {
    --background: oklch(1 0 0);
    --foreground: oklch(0.145 0 0);
    --card: oklch(1 0 0);
    --card-foreground: oklch(0.145 0 0);
    --primary: oklch(0.205 0 0);
    --primary-foreground: oklch(0.985 0 0);
    --secondary: oklch(0.97 0 0);
    --secondary-foreground: oklch(0.205 0 0);
    --muted: oklch(0.97 0 0);
    --muted-foreground: oklch(0.556 0 0);
    --destructive: oklch(0.577 0.245 27.325);
    --border: oklch(0.922 0 0);
    --input: oklch(0.922 0 0);
    --ring: oklch(0.708 0 0);
    --radius: 0.625rem;
  }
}

@layer base {
  * {
    border-color: var(--border);
  }
  body {
    background-color: var(--background);
    color: var(--foreground);
  }
}
```

NOTA: Este CSS representa o tema neutral do shadcn/ui adaptado para Tailwind v4 (que usa
oklch em vez de hsl). O `npx shadcn@latest init` geraria algo similar — usamos este
conteúdo manual para evitar o modo interativo do CLI em Docker/CI (Pitfall 4 da pesquisa).

### Passo 2 — Criar src/lib/utils.ts manualmente

O `npx shadcn@latest init` gera este arquivo automaticamente. Criá-lo manualmente evita
o modo interativo do CLI:

Criar `frontend/src/lib/utils.ts`:

```typescript
import { clsx, type ClassValue } from "clsx";
import { twMerge } from "tailwind-merge";

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs));
}
```

Instalar as dependências do cn() se não presentes (instaladas automaticamente pelo shadcn init):

```bash
cd frontend && npm install clsx tailwind-merge class-variance-authority lucide-react
```

### Passo 3 — Criar components.json para o CLI shadcn

Criar `frontend/components.json`:

```json
{
  "$schema": "https://ui.shadcn.com/schema.json",
  "style": "default",
  "rsc": false,
  "tsx": true,
  "tailwind": {
    "config": "",
    "css": "src/globals.css",
    "baseColor": "neutral",
    "cssVariables": true,
    "prefix": ""
  },
  "aliases": {
    "components": "@/components",
    "utils": "@/lib/utils",
    "ui": "@/components/ui",
    "lib": "@/lib",
    "hooks": "@/hooks"
  },
  "iconLibrary": "lucide"
}
```

NOTA: `"rsc": false` é crítico — este projeto não usa React Server Components. `"config": ""`
indica Tailwind v4 (sem tailwind.config.js). Sem este arquivo, `npx shadcn@latest add` falha.

### Passo 4 — Criar src/main.tsx (entry point atualizado)

O entry point atual é `src/client.tsx`. Criar `frontend/src/main.tsx` como substituto:

```tsx
import { createRoot } from "react-dom/client";
import "@/globals.css";

function App() {
  return (
    <main className="min-h-screen bg-background flex items-center justify-center">
      <div className="text-center space-y-4">
        <h1 className="text-3xl font-bold text-foreground">Onboarding</h1>
        <p className="text-muted-foreground">Frontend Foundation — Wave 1 completa</p>
      </div>
    </main>
  );
}

const rootEl = document.getElementById("root");
if (!rootEl) throw new Error("Elemento #root não encontrado no DOM");
createRoot(rootEl).render(<App />);
```

NOTA: RouterProvider será adicionado em 07-02-PLAN.md. Por ora, App renderiza diretamente.
A importação `@/globals.css` é obrigatória — sem ela Tailwind v4 não gera nenhum estilo
(Pitfall 6 da pesquisa: o plugin Vite só processa arquivos no grafo de módulos).
