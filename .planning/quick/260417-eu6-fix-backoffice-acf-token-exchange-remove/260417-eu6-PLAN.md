<objective>
Remover `offline_access` do scope solicitado pelo fluxo Authorization Code + PKCE do backoffice. Atualmente o browser recebe um redirect para `/auth/error?error=Token%20exchange%20failed%3A%20400%20%7B%22error%22%3A%22not_allowed%22%2C%22error_description%22%3A%22Offline%20tokens%20not%20allowed%20for%20the%20user%20or%20client%22%7D` porque o client `onboarding-backoffice` / usuário admin não tem permissão para emitir offline tokens.

Purpose: O backoffice não precisa de offline tokens — a sessão deve expirar quando o admin sair; o refresh token normal cobre a renovação durante uma sessão ativa. Esta é a correção mínima de 1 linha que desbloqueia o login ACF do backoffice sem alterar a configuração do Keycloak.

Output: Uma linha alterada em `frontend/backoffice/src/lib/auth-code-flow.ts` (linha 37) — de `scope: "openid offline_access"` para `scope: "openid profile email"`.
</objective>

```

Altere para:

scope: "openid profile email",
```

**Por que essa substituição específica:**
- `openid` — obrigatório para OIDC (mantém behavior do ID token).
- `profile` e `email` — padrão OIDC que garante que claims como `name`, `preferred_username` e `email` venham no access token (o handler `/auth/me` em `auth-server.ts` linhas 178-188 já depende desses claims; sem `profile`/`email` o fallback funciona mas o `email` não seria preenchido).
- **Não** voltar a incluir `offline_access` — o client `onboarding-backoffice` e/ou o usuário admin não têm o role `offline_access` no Keycloak, e o backoffice não precisa dele (sessões devem expirar quando o admin sair).

Não altere nenhuma outra linha. Não mexa em `auth-server.ts`, `exchangeCodeForTokens`, `refreshAccessToken`, ou nos outros helpers. A assinatura pública de `buildAuthorizationUrl` permanece idêntica.
