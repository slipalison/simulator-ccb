**Phase 29 Requirements (from STATE.md):**

**REQ-V5.0-01 — Troca obrigatória de senha no primeiro login:**
- Admin seedado (`admin@onboarding.local`) muda `"temporary": false` para `"temporary": true` no realm.json
- Quando admin faz login pela primeira vez, sistema detecta e redireciona para tela de troca de senha
- Novos admins criados pelo backoffice também recebem `temporary: true` via Keycloak Admin API

**REQ-V5.0-02 — Criação de novos admins pelo backoffice:**
- Admin autenticado preenche nome + email do novo admin
- Sistema gera senha temporária aleatória e cria usuário no Keycloak com role "admin"
- Senha temporária é exibida na tela para quem criou comunicar ao novo admin

**REQ-V5.0-03 — Audit log imutável + visível com filtros:**
- Todas as ações administrativas são registradas (criação de admin, login/logout, edições, bloqueios, exclusões)
- Audit log é append-only (imutável) no banco de dados
- Visível no backoffice com filtros por: data, tipo de ação, usuário que realizou ação

**Architecture constraints:**
- `frontend/backoffice` is independent — no imports from `frontend/client`
- All admin endpoints require `[Authorize(Roles = "admin")]`
- Keycloak Admin API uses `manage-users` role service account
- Audit log is append-only: no UPDATE or DELETE allowed on AdminAuditLog entities

       - Result: CreateAdminResult { AdminId (Guid), TemporaryPassword (string) }

    2. Create `CreateAdminCommandValidator` (FluentValidation):
       - FullName: Required, Length 2-200
       - Email: Required, EmailAddress format

    3. Create `CreateAdminCommandHandler`:
       - Dependencies: IKeycloakAdminUserService, IAuditLogRepository, IHttpContextAccessor (for IP address)
       - Steps:
         a. Validate email uniqueness (check if email exists in Keycloak)
         b. Generate random temporary password (min 12 chars, meets Keycloak password policy: uppercase, lowercase, digit, special char)
         c. Create user in Keycloak via Admin API with:
            - temporary: true
            - roles: ["admin"]
            - enabled: true
         d. Create AdminAuditLog entry: ActionType.AdminCreated, details include email and creator info
         e. Return CreateAdminResult with AdminId and TemporaryPassword
       - Error handling: If Keycloak creation fails, DO NOT persist anything — return error

    Password generation:
    - Use RandomNumberGenerator for cryptographic randomness
    - 12-16 characters, guaranteed: 2 uppercase, 2 lowercase, 2 digits, 2 special chars, rest random from all categories
    - Return as plain string (only visible in API response, never logged)

    What to avoid:
    - Do NOT store the temporary password in the database — only in the response
    - Do NOT log the temporary password anywhere
    - Do NOT send the password via email — display only in API response for the creator to communicate
  </action>

  <done>CreateAdminCommand, validator, and handler compile successfully</done>
