## Technical Details

### CI Job (Conditional)

```yaml
iac-kubescape:
  name: IaC — Kubescape
  runs-on: ubuntu-latest
  if: github.event_name == 'push' || github.event_name == 'pull_request'
  permissions:
    contents: read
    security-events: write
  steps:
    - uses: actions/checkout@v4

    - name: Check for K8s manifests
      id: check-k8s
      run: |
        if find infra/ -name '*.yaml' -o -name '*.yml' | grep -q '.'; then
          echo "has-k8s=true" >> $GITHUB_OUTPUT
        else
          echo "has-k8s=false" >> $GITHUB_OUTPUT
          echo "No K8s manifests found — skipping Kubescape scan"
        fi

    - name: Run Kubescape scan
      if: steps.check-k8s.outputs.has-k8s == 'true'
      uses: kubescape/kubescape-action@v1
      with:
        path: infra/
        format: sarif
        output: kubescape-results.sarif
        fail-threshold: high
        compliance-frameworks: NSA,CIS

    - name: Upload Kubescape SARIF
      if: always() && steps.check-k8s.outputs.has-k8s == 'true'
      uses: github/codeql-action/upload-sarif@v4
      with:
        sarif_file: kubescape-results.sarif
        category: kubescape
```

### `docs/iac-policies.md` Structure

The document should cover:

1. **Docker Compose Security**
   - No `privileged: true`
   - No `--cap-add ALL`
   - Resource limits (memory, CPU)
   - HEALTHCHECK on all services
   - Secrets via `.env` file, not hardcoded
   - Network isolation (internal networks)
   - Read-only filesystems where possible

2. **Future Kubernetes Policies** (preparation)
   - Pod security standards (restricted)
   - Resource quotas and limits
   - Network policies
   - Service account restrictions
   - Image pull policies (always use pinned digests)

3. **Suppression Workflow**
   - How to add exceptions to `.checkov.yml`
   - How to suppress Kubescape findings
   - Required justification format
