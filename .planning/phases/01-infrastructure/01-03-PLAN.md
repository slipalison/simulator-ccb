Use the `dotnet` CLI to create the solution and projects. Run these commands from the repo root:

```bash
# Create solution
dotnet new sln -n Onboarding -o .

# Create Domain (class library, no framework deps)
dotnet new classlib -n Onboarding.Domain -o src/Onboarding.Domain --framework net10.0
rm src/Onboarding.Domain/Class1.cs

# Create Application (class library)
dotnet new classlib -n Onboarding.Application -o src/Onboarding.Application --framework net10.0
rm src/Onboarding.Application/Class1.cs

# Create Infrastructure (class library)
dotnet new classlib -n Onboarding.Infrastructure -o src/Onboarding.Infrastructure --framework net10.0
rm src/Onboarding.Infrastructure/Class1.cs

# Create API (ASP.NET Core — Controllers, no Minimal API, no https redirect in dev container)
dotnet new webapi -n Onboarding.API -o src/Onboarding.API --framework net10.0 --use-controllers --no-https

# Add projects to solution
dotnet sln add src/Onboarding.Domain/Onboarding.Domain.csproj
dotnet sln add src/Onboarding.Application/Onboarding.Application.csproj
dotnet sln add src/Onboarding.Infrastructure/Onboarding.Infrastructure.csproj
dotnet sln add src/Onboarding.API/Onboarding.API.csproj

# Add project references (DDD dependency rule)
dotnet add src/Onboarding.Application/Onboarding.Application.csproj reference src/Onboarding.Domain/Onboarding.Domain.csproj
dotnet add src/Onboarding.Infrastructure/Onboarding.Infrastructure.csproj reference src/Onboarding.Domain/Onboarding.Domain.csproj
dotnet add src/Onboarding.Infrastructure/Onboarding.Infrastructure.csproj reference src/Onboarding.Application/Onboarding.Application.csproj
dotnet add src/Onboarding.API/Onboarding.API.csproj reference src/Onboarding.Domain/Onboarding.Domain.csproj
dotnet add src/Onboarding.API/Onboarding.API.csproj reference src/Onboarding.Application/Onboarding.Application.csproj
dotnet add src/Onboarding.API/Onboarding.API.csproj reference src/Onboarding.Infrastructure/Onboarding.Infrastructure.csproj
```

Create `src/Onboarding.API/Dockerfile` using explicit COPY per project (not glob) to guarantee
layer caching with multi-project solutions:
```dockerfile
FROM mcr.microsoft.com/dotnet/sdk:10.0 AS dev
WORKDIR /app

# Copy solution and project files for layer caching
COPY Onboarding.sln .
COPY src/Onboarding.Domain/Onboarding.Domain.csproj src/Onboarding.Domain/
COPY src/Onboarding.Application/Onboarding.Application.csproj src/Onboarding.Application/
COPY src/Onboarding.Infrastructure/Onboarding.Infrastructure.csproj src/Onboarding.Infrastructure/
COPY src/Onboarding.API/Onboarding.API.csproj src/Onboarding.API/
RUN dotnet restore

# Copy source
COPY src/ ./src/

WORKDIR /app/src/Onboarding.API
EXPOSE 8080
ENTRYPOINT ["dotnet", "watch", "run", "--no-launch-profile", "--urls", "http://0.0.0.0:8080"]
```

Create `frontend/app.config.ts` (Vinxi SPA config with Docker HMR — usePolling is REQUIRED
on Windows Docker to propagate file changes from the bind-mounted host filesystem):
```typescript
import { defineConfig } from "vinxi";

export default defineConfig({
  routers: [
    {
      name: "public",
      type: "static",
      dir: "./public",
    },
    {
      name: "client",
      type: "spa",
      handler: "./src/client.tsx",
      vite: {
        server: {
          host: "0.0.0.0",
          port: 5173,
          hmr: {
            host: "localhost",
            port: 5173,
            clientPort: 5173,
          },
          watch: {
            usePolling: true,   // Required: inotify events unreliable in Docker on Windows
            interval: 1000,
          },
        },
      },
    },
  ],
});
```
