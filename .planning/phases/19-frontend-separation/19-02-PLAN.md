# Phase 19 — Plan 02: Frontend Backoffice Migration + Monolith Cleanup

## Objective

Criar o projeto `frontend/backoffice` independente, migrar todas as telas e componentes admin, remover o `frontend/` monolith original, limpar rotas admin do client, e validar que ambos projetos rodam independentemente.

## Execution Context

**Strategy:** Copy-first-then-delete — criar backoffice completo antes de deletar monolith. Validar ambos antes de remover original.

**Port:** 5174 (nova porta para backoffice)

**What migrates para backoffice:**
- Pages: AdminLoginPage, AdminAccessDeniedPage, AdminUsersPage, AdminUserDetailPage, NotFoundPage
- Molecules: AdminLoginForm, AdminUsersTable, AdminPagination, AdminStatusFilter, AdminSearchBar, KeycloakStatusBadge, UserDetailCard
- Templates: AdminLayout
- Libs: admin-auth-context.tsx, admin-api.ts, admin-error-handler.ts, admin-http-interceptor.ts, utils.ts, theme-provider.tsx
- UI: Todos os 13 componentes shadcn/ui (duplicados do client)
- Tests: Todos os testes admin

**What LIMPAR no client:**
- router.tsx — remover TODAS as rotas /admin/*
- main.tsx — remover AdminAuthProvider (se ainda presente)

## Context

**Source:** `frontend/` monolith atual (será deletado após validação)

**State after Plan 01:**
- `frontend/client/` existe e funciona (porta 5173)
- `compose.yaml` tem serviço `frontend-client` + `frontend` original
- Monolith ainda existe com TODAS as rotas (public + admin)

**Research findings:**
- Admin components já têm auth separado (AdminAuthProvider) — sem conflito de sessão
- Admin API usa `/api/admin/*` endpoints — proxy é idêntico ao client
- Admin auth usa cookies httpOnly — diferente do client (memory tokens)
- Admin router tem 4 rotas: /admin/login, /admin/access-denied, /admin/users, /admin/users/$id
