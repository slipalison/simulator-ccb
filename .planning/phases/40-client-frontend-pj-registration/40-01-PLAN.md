<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client (browser) → API | Untrusted input — all employee actions must use companyId from auth context, not from URL params |
| Client (browser) → Keycloak | ACF redirect — tokens never exposed to JS (httpOnly cookies) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-40-01 | Spoofing | auth-context | mitigate | /auth/me response with group info over httpOnly cookies — server is source of truth for permissions, not client state |
| T-40-02 | Tampering | Employee API calls | mitigate | companyId comes from auth context (server-validated claim), never from user input — prevents cross-company data access |
| T-40-03 | Information disclosure | PF removal | mitigate | All PF-specific schemas, types, routes, and components removed — no PF data leakage |
| T-40-04 | Elevation of privilege | Sidebar visibility | accept | Client-side route hiding is UX-only — backend permission policies (Phase 39) enforce real access control |
</threat_model>
