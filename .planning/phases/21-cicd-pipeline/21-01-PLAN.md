# Plan 21-01 — GitHub Actions Workflow Scaffold + .NET 10 Build + Test + Coverage

## Overview

Create the foundational `.github/workflows/ci.yml` with the backend job fully operational: .NET 10 SDK setup, NuGet caching, build, test execution, and 80% line coverage enforcement using `coverlet.msbuild`.

**Prerequisite migration:** Replace `coverlet.collector` with `coverlet.msbuild` in all 3 test projects to enable threshold enforcement.

## Success Criteria

1. ✅ `.github/workflows/ci.yml` exists with `backend` job that triggers on push to main, PRs to main, and manual dispatch
2. ✅ Backend job: checkout → setup .NET 10 → cache NuGet → restore → build → test with coverage
3. ✅ `coverlet.msbuild` replaces `coverlet.collector` in all 3 test `.csproj` files
4. ✅ Coverage threshold of 80% line coverage enforced — job fails if < 80%
5. ✅ `dotnet build` succeeds with `--configuration Release` and no critical warnings
6. ✅ All existing tests pass in CI (xUnit domain, API, integration tests)
7. ✅ Workflow file is valid YAML — passes `actionlint` or GitHub workflow validation

## Technical Details

### Test Projects to Migrate

| Project | Current Package | New Package |
|---------|----------------|-------------|
| `Onboarding.Domain.Tests` | `coverlet.collector` v8.0.1 | `coverlet.msbuild` v6.0.3+ |
| `Onboarding.API.Tests` | `coverlet.collector` v8.0.1 | `coverlet.msbuild` v6.0.3+ |
| `Onboarding.Integration.Tests` | `coverlet.collector` v6.0.4 | `coverlet.msbuild` v6.0.3+ |

### coverlet.msbuild PackageReference

```xml
<PackageReference Include="coverlet.msbuild" Version="6.0.3">
  <IncludeAssets>runtime; build; native; contentfiles; analyzers; buildtransitive</IncludeAssets>
  <PrivateAssets>all</PrivateAssets>
</PackageReference>
```

Remove the `coverlet.collector` PackageReference entirely. Do NOT keep both — they conflict and cause duplicate instrumentation.

### Coverage CLI Command

```bash
dotnet test Onboarding.slnx \
  --no-build \
  --configuration Release \
  /p:CollectCoverage=true \
  /p:Threshold=80 \
  /p:ThresholdType=line \
  /p:ThresholdStat=total \
  /p:CoverletOutputFormat=cobertura
```

**Why `ThresholdStat=total`:** The project has 3 test assemblies (Domain, API, Integration). Using `total` enforces 80% aggregate line coverage across all assemblies, not 80% per-assembly. This prevents a scenario where one focused test project at 100% passes while another at 40% drags down overall coverage.

### Workflow Structure (Backend Job Only)

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]
  workflow_dispatch:

permissions: read-all

jobs:
  backend:
    name: Backend (.NET 10)
    runs-on: ubuntu-latest
    permissions:
      contents: read
    steps:
      - uses: actions/checkout@v4

      - name: Setup .NET 10
        uses: actions/setup-dotnet@v4
        with:
          dotnet-version: "10.0.x"

      - name: Cache NuGet packages
        uses: actions/cache@v5
        with:
          path: ~/.nuget/packages
          key: ${{ runner.os }}-nuget-${{ hashFiles('**/*.csproj') }}
          restore-keys: |
            ${{ runner.os }}-nuget-

      - name: Restore dependencies
        run: dotnet restore Onboarding.slnx

      - name: Build
        run: dotnet build Onboarding.slnx --no-restore --configuration Release

      - name: Test with coverage
        run: >
          dotnet test Onboarding.slnx
          --no-build
          --configuration Release
          --verbosity normal
          /p:CollectCoverage=true
          /p:Threshold=80
          /p:ThresholdType=line
          /p:ThresholdStat=total
          /p:CoverletOutputFormat=cobertura
```

## Tasks

### Task 1: Create `.github/workflows/ci.yml` with backend job scaffold
**What:** Create the directory structure and write the initial workflow YAML with the backend job (steps: checkout, setup .NET, cache, restore, build, test).
**Test approach:** Validate YAML syntax with `actionlint` or a simple YAML parser. Verify workflow triggers are correct by checking `on:` section. No runtime test needed at this stage — file existence and structure is the deliverable.
**Validation:** File exists at `.github/workflows/ci.yml`, contains `jobs: backend:`, has `actions/checkout@v4`, `actions/setup-dotnet@v4`, `actions/cache@v5`.

### Task 2: Migrate `Onboarding.Domain.Tests.csproj` from coverlet.collector to coverlet.msbuild
**What:** Replace `<PackageReference Include="coverlet.collector" Version="8.0.1" />` with `<PackageReference Include="coverlet.msbuild" Version="6.0.3">` including the `<IncludeAssets>` and `<PrivateAssets>` elements.
**Test approach:**
- Unit test: Verify the `.csproj` file contains `coverlet.msbuild` and does NOT contain `coverlet.collector`
- Integration test: Run `dotnet test tests/Onboarding.Domain.Tests --no-build /p:CollectCoverage=true` — should produce coverage output without errors
**Validation:** `dotnet test` runs successfully, coverage XML file generated, no file lock errors.

### Task 3: Migrate `Onboarding.API.Tests.csproj` from coverlet.collector to coverlet.msbuild
**What:** Same migration as Task 2 — replace `coverlet.collector` v8.0.1 with `coverlet.msbuild` v6.0.3.
**Test approach:**
- Unit test: Verify `.csproj` contains `coverlet.msbuild`, no `coverlet.collector`
- Integration test: Run `dotnet test tests/Onboarding.API.Tests --no-build /p:CollectCoverage=true` — coverage output generated
**Validation:** All API tests pass, coverage data collected, no conflicts with other test infrastructure.

### Task 4: Migrate `Onboarding.Integration.Tests.csproj` from coverlet.collector to coverlet.msbuild
**What:** Same migration — replace `coverlet.collector` v6.0.4 with `coverlet.msbuild` v6.0.3.
**Test approach:**
- Unit test: Verify `.csproj` contains `coverlet.msbuild`, no `coverlet.collector`
- Integration test: Run `dotnet test tests/Onboarding.Integration.Tests --no-build /p:CollectCoverage=true` — note: integration tests use Testcontainers (PostgreSQL, Keycloak). In CI, these containers need to start. Verify `CI=true` environment variable doesn't break test container timeouts.
**Validation:** Integration tests pass with coverage collection. No file lock issues from parallel test execution.

### Task 5: Add coverage threshold enforcement to workflow test step
**What:** Update the `dotnet test` command in `ci.yml` to include `/p:Threshold=80 /p:ThresholdType=line /p:ThresholdStat=total /p:CoverletOutputFormat=cobertura`.
**Test approach:** 
- Dry run locally: `dotnet test Onboarding.slnx --no-build --configuration Release /p:CollectCoverage=true /p:Threshold=80 /p:ThresholdType=line /p:ThresholdStat=total`
- Verify the command exits with non-zero if threshold is not met (can test with artificially high threshold like `/p:Threshold=99` to confirm failure behavior)
**Validation:** Workflow file contains all 4 threshold parameters. Local dry-run either passes (coverage >= 80%) or fails with clear "Coverage threshold was not met" message.

### Task 6: Verify end-to-end backend CI locally
**What:** Run the complete CI pipeline locally to validate: `dotnet restore` → `dotnet build --configuration Release` → `dotnet test` with coverage threshold.
**Test approach:** Execute the exact commands from the workflow file on the local machine. Capture exit codes. Verify no warnings, no file locks, no test failures.
**Validation:**
- `dotnet restore Onboarding.slnx` — exit 0
- `dotnet build Onboarding.slnx --no-restore --configuration Release` — exit 0, no critical warnings
- `dotnet test Onboarding.slnx --no-build --configuration Release /p:CollectCoverage=true /p:Threshold=80 /p:ThresholdType=line /p:ThresholdStat=total` — exit 0 (or clear failure message if coverage < 80%)
- Coverage file `coverage.cobertura.xml` generated in test output directories

## Risk Assessment

| Risk | Probability | Impact | Mitigation |
|------|------------|--------|------------|
| `coverlet.msbuild` file lock issues with parallel tests | Medium | Medium | Run tests sequentially in CI (`--no-parallel` flag if needed). Test projects run independently on solution file — not truly parallel. |
| Integration tests timeout in CI (Testcontainers slow startup) | Medium | High | Add `CI=true` env var to workflow. Increase container startup timeouts in test code if needed. |
| Coverage threshold too high (current coverage < 80%) | Low | Medium | Run coverage locally first to check current level. If < 80%, either lower threshold temporarily or add tests. |
| `.csproj` migration breaks local dev test runs | Low | Low | `coverlet.msbuild` only activates with `/p:CollectCoverage=true`. Normal `dotnet test` without coverage flags works identically. |
| `actions/cache@v5` requires runner >= 2.327.1 | Low | Low | GitHub-hosted `ubuntu-latest` should meet this. If not, fall back to `actions/cache@v4`. |
