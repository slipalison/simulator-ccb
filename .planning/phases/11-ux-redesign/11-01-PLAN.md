# Phase 11 — Plan 01: Unified Registration Form + Login-First Navigation

## Objective

Consolidar o fluxo de cadastro fragmentado (2 telas) em um formulário único inteligente com PF/PJ dinâmico, adicionar password UX completa, e reorganizar a navegação para login-first com auto-login pós-cadastro.

**Requisitos atendidos:** UX-01, UX-02, UX-03, UX-04, UX-06

## Execution Context

### Project State
- **Milestone:** v1.0 COMPLETE (10 phases, 30 plans, 135 tests)
- **Current:** Iniciando v2.0 — UX Redesign (P0 priority)
- **Frontend:** Vinxi SPA com Atomic Design, TanStack Router, React Hook Form + Zod, Tailwind v4
- **Backend:** .NET 10 API com Keycloak integration, JWT auth, registration endpoints funcionando
- **Tests:** 135 tests passing (44 API + 44 domain + 47 frontend)

### Current Registration Flow (PROBLEMA)
```
Home Page (genérica)
  ↓ click "Criar conta"
RegistrationTypeSelector (escolhe PF ou PJ)
  ↓ click
PfRegistrationForm OU PjRegistrationForm
  ↓ submit
API cria user
  ↓ 201
Redirect para /login
  ↓ usuario digita credenciais
Login
  ↓ submit
Profile
```
**Total clicks:** 4+ | **Telas:** 3 | **Tempo:** ~60s

### Target Flow (SOLUÇÃO)
```
/ (root) → LoginPage (se não logado)
  ↓ click "Criar conta"
RegistrationForm (única tela, radio PF/PJ)
  ↓ submit + auto-login
Profile (já logado)
```
**Total clicks:** 2 | **Telas:** 2 | **Tempo:** ~30s

### Files to Modify
- **Criar:** `RegistrationForm.tsx`, `PersonTypeRadio.tsx`, `PasswordStrengthMeter.tsx`, `PasswordField.tsx`
- **Modificar:** `router.tsx`, `LoginPage.tsx`, `auth-context.tsx`, `validation-schemas.ts`, `api.ts`
- **Remover:** `RegistrationTypeSelector.tsx`, `PfRegistrationForm.tsx`, `PjRegistrationForm.tsx`

### Technical Decisions Already Made
1. **Zod dynamic schema** com `superRefine()` para validação condicional PF/PJ (documentado em PHASE-11-UX-REDESIGN.md)
2. **Password strength algorithm:** 0-100 score baseado em critérios objetivos (minLength, upper, lower, digit, special, length>=12)
3. **Auto-login:** Após 201 do registro, chamar `loginClient(email, password)` automaticamente; fallback para `/login` se falhar
4. **Login-first:** Route `/` redireciona para LoginPage; se já logado, redirect automático para `/profile`

### Risks & Mitigations
| Risk | Impact | Mitigation |
|------|--------|------------|
| Radio button PF/PJ confuso | Alto | Labels claros: "Pessoa Física (CPF)" / "Pessoa Jurídica (CNPJ)" |
| Auto-login falhar silenciosamente | Alto | Fallback explícito para `/login` com mensagem |
| Trocar PF→PJ não limpar campos | Médio | `watch('personType')` com `useEffect` para reset de campos condicionais |
| Password strength subjetivo | Médio | Algoritmo objetivo (especificado em PHASE-11-UX-REDESIGN.md) |

   // Root route com lógica de redirect
   const rootRoute = createRoute({
     path: '/',
     component: () => {
       const { isAuthenticated } = useAuth();
       useEffect(() => {
         if (isAuthenticated) navigate('/profile');

     },
