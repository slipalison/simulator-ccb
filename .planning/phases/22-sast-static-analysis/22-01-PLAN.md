# Plan 22-01 — Semgrep Configuration, Custom Rules for C#/React, CI Integration

## Overview

Install Semgrep in the CI pipeline, create custom security rules targeting the project's specific attack surface (localStorage tokens, XSS, hardcoded credentials, CSRF, CPF/CNPJ domain integrity), and wire results to GitHub Security Tab via SARIF upload.

## Success Criteria

1. ✅ `.semgrep/` directory exists with 6 custom YAML rules covering: localStorage tokens, dangerouslySetInnerHTML, hardcoded credentials, missing CSRF, raw CPF/CNPJ comparison, insecure deserialization
2. ✅ `.semgrepignore` configured to exclude build outputs, dependencies, generated code, test config samples
3. ✅ `sast-semgrep` job in `.github/workflows/ci.yml` runs `semgrep scan` with `--config auto --config .semgrep/`
4. ✅ SARIF results uploaded to GitHub Security Tab via `github/codeql-action/upload-sarif@v4` with `category: semgrep`
5. ✅ Semgrep scan fails on ERROR severity rules, passes WARNING rules (posted to Security Tab only)
6. ✅ Custom rules validated against current codebase — at least 1 real finding (or intentional false positive test confirms rule works)
7. ✅ `pip install semgrep` used directly — NOT deprecated `returntocorp/semgrep-action`

## Scope

### In Scope
- `.semgrep/` directory with 6 custom rule files
- `.semgrepignore` file
- `sast-semgrep` job in `ci.yml`
- SARIF upload step

## Technical Details

### Custom Rules

| Rule File | Severity | Language | Detects |
|-----------|----------|----------|---------|
| `no-localstorage-tokens.yaml` | ERROR | TypeScript/JS | `localStorage.setItem/getItem` with token-related keys |
| `no-dangerously-set-inner-html.yaml` | ERROR | TSX/JSX | `dangerouslySetInnerHTML` usage |
| `no-hardcoded-credentials.yaml` | ERROR | C# | Connection strings with passwords, API key patterns (sk-, ghp_, AKIA) |
| `no-missing-csrf.yaml` | ERROR | C# | `[HttpPost]` without `[ValidateAntiForgeryToken]` |
| `no-raw-cpf-cnpj-comparison.yaml` | WARNING | C# | String comparison of 11-digit or 14-digit numbers against CPF/CNPJ patterns |
| `no-insecure-deserialization.yaml` | ERROR | C# | `BinaryFormatter`, `TypeNameHandling.Auto/All` |

### CI Job

```yaml
sast-semgrep:
  name: SAST — Semgrep
  runs-on: ubuntu-latest
  permissions:
    contents: read
    security-events: write
  steps:
    - uses: actions/checkout@v4

    - name: Install Semgrep
      run: pip install semgrep

    - name: Run Semgrep Scan
      run: |
        semgrep scan \
          --config auto \
          --config .semgrep/ \
          --output semgrep.sarif \
          --sarif \
          --error \
          --metrics off

    - name: Upload Semgrep SARIF
      uses: github/codeql-action/upload-sarif@v4
      if: always()
      with:
        sarif_file: semgrep.sarif
        category: semgrep
```

### `--error` Flag Behavior

The `--error` flag makes Semgrep exit with non-zero status if any findings have severity `ERROR`. Findings with severity `WARNING` or `INFO` are still reported in SARIF but do NOT fail the job. This is the desired behavior — ERROR blocks merge, WARNING posts to Security Tab for review.

## Tasks

### Task 1: Create `.semgrepignore`
**What:** Create `.semgrepignore` at project root excluding: `**/bin/`, `**/obj/`, `**/node_modules/`, `**/.vinxi/`, `**/Migrations/`, `**/appsettings.Development.json`, `**/.env.example`, `**/*.md`.
**Test approach:** Run `semgrep scan --config auto .` — verify no errors about excluded paths. Check output does not include findings from excluded directories.
**Validation:** `.semgrepignore` exists. Excluded paths confirmed in scan output.

### Task 2: Create `.semgrep/no-localstorage-tokens.yaml`
**What:** Create Semgrep rule detecting `localStorage.setItem/getItem` with token-related keys (token, access_token, refresh_token, session, auth, jwt, bearer). Severity: ERROR. Languages: typescript, javascript.
**Test approach:** Create a test TypeScript file with `localStorage.setItem('authToken', token)` and run `semgrep scan --config .semgrep/no-localstorage-tokens.yaml test.ts`. Verify it triggers the rule. Then test with `localStorage.setItem('theme', 'dark')` — verify no trigger.
**Validation:** Rule detects token-related localStorage. Does NOT trigger on benign localStorage usage.

### Task 3: Create `.semgrep/no-dangerously-set-inner-html.yaml`
**What:** Create rule detecting `dangerouslySetInnerHTML` in React/TSX. Severity: ERROR. Languages: typescript, javascript, tsx, jsx.
**Test approach:** Create test TSX with `dangerouslySetInnerHTML={{ __html: html }}` — verify trigger. Create component without it — verify no trigger.
**Validation:** Rule triggers on dangerouslySetInnerHTML. Message includes remediation guidance (use DOMPurify).

### Task 4: Create `.semgrep/no-hardcoded-credentials.yaml`
**What:** Create rule detecting hardcoded connection strings (Server=...Password=...), API key patterns (sk-, ghp_, xoxb-, AKIA). Severity: ERROR. Languages: csharp.
**Test approach:** Create test C# file with `var conn = "Server=localhost;Password=secret123;"` — verify trigger. Test with `var name = "John"` — verify no trigger. Test with IConfiguration pattern `_configuration["ConnectionStrings:Default"]` — verify no trigger.
**Validation:** Rule detects hardcoded creds. Does NOT trigger on IConfiguration or environment variable patterns.

### Task 5: Create `.semgrep/no-missing-csrf.yaml`
**What:** Create rule detecting `[HttpPost]` methods without `[ValidateAntiForgeryToken]`. Severity: ERROR. Languages: csharp.
**Test approach:** Create test C# controller with `[HttpPost] public IActionResult Submit() { }` — verify trigger. Add `[ValidateAntiForgeryToken]` — verify no trigger. Add `[AutoValidateAntiforgeryToken]` at class level — verify still triggers (use `// nosem` for suppression).
**Validation:** Rule detects missing CSRF. Message includes remediation guidance.

### Task 6: Create `.semgrep/no-raw-cpf-cnpj-comparison.yaml`
**What:** Create rule detecting string comparison of 11-digit or 14-digit numbers that look like CPF/CNPJ. Severity: WARNING (not ERROR — may have legitimate uses). Languages: csharp.
**Test approach:** Create test C# with `if (input == "12345678901")` — verify trigger. Test with `client.Cpf.ToString()` — verify no trigger (uses VO). Test with `if (count == 123)` — verify no trigger (not 11/14 digits).
**Validation:** Rule detects raw CPF/CNPJ string comparisons. Does NOT trigger on domain Value Object usage.

### Task 7: Create `.semgrep/no-insecure-deserialization.yaml`
**What:** Create rule detecting `BinaryFormatter`, `JavaScriptSerializer`, `TypeNameHandling.Auto/All`. Severity: ERROR. Languages: csharp.
**Test approach:** Create test C# with `var formatter = new BinaryFormatter();` — verify trigger. Test with `JsonSerializer.Serialize(obj)` — verify no trigger.
**Validation:** Rule detects insecure deserialization patterns. Does NOT trigger on safe System.Text.Json usage.

### Task 8: Add `sast-semgrep` job to `ci.yml`
**What:** Append the `sast-semgrep` job to `.github/workflows/ci.yml` alongside existing jobs. No `needs:` — runs in parallel. Includes checkout, pip install semgrep, scan, SARIF upload.
**Test approach:** Validate YAML syntax. Verify job has `security-events: write` permission. Verify `--config auto --config .semgrep/` in scan command. Verify `--error` flag present. Verify SARIF upload with `category: semgrep`.
**Validation:** Job exists in ci.yml. No `needs:` key. All 4 steps present. Permissions correct.

### Task 9: Validate rules against current codebase
**What:** Run `semgrep scan --config auto --config .semrep/ .` locally. Review all findings. Document which rules found real issues and which need tuning.
**Test approach:** Execute scan on project root. Categorize findings: (a) real security issues, (b) false positives, (c) intentional patterns (with nosem). For false positives, tune rule regex or add to `.semgrepignore`.
**Validation:** Scan completes. Findings documented. At least 1 custom rule produced a finding OR test file confirms rule works. False positives tuned.
