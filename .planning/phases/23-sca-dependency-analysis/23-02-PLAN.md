# Plan 23-02 — Trivy Filesystem Scanning + SARIF Export + Vulnerability Threshold Enforcement

## Overview

Integrate Trivy into the CI pipeline for filesystem-based dependency vulnerability scanning. Trivy analyzes `package-lock.json`, `*.csproj`, and `Dockerfile` files for known CVEs. Results uploaded to GitHub Security Tab via SARIF. Scan fails on CRITICAL or HIGH vulnerabilities without available fix.

## Success Criteria

1. ✅ `sca-trivy` job in `ci.yml` runs `trivy fs --scanners vuln .`
2. ✅ SARIF results uploaded via `github/codeql-action/upload-sarif@v4` with `category: trivy`
3. ✅ Scan fails if CRITICAL or HIGH CVEs found without fix
4. ✅ Trivy installed via `aquasecurity/trivy-action@master` (official GitHub Action)
5. ✅ Ignore file (`.trivyignore`) configured for known acceptable risks
6. ✅ Scan completes in under 5 minutes on `ubuntu-latest`

## Scope

### In Scope
- `sca-trivy` job in `.github/workflows/ci.yml`
- `.trivyignore` file for acceptable vulnerabilities
- Trivy filesystem scanning with vulnerability detection
- SARIF upload to GitHub Security Tab

### Out of Scope
- Container image scanning — handled in Phase 24
- IaC scanning — handled in Phase 25
- Secrets detection — handled in Phase 26
- Auto-fix of vulnerabilities — manual review process

## Technical Details

### CI Job

```yaml
sca-trivy:
  name: SCA — Trivy
  runs-on: ubuntu-latest
  permissions:
    contents: read
    security-events: write
  steps:
    - uses: actions/checkout@v4

    - name: Run Trivy filesystem scan
      uses: aquasecurity/trivy-action@master
      with:
        scan-type: fs
        scan-ref: .
        format: sarif
        output: trivy-results.sarif
        severity: CRITICAL,HIGH
        exit-code: "1"
        ignore-unfixed: true

    - name: Upload Trivy SARIF
      uses: github/codeql-action/upload-sarif@v4
      if: always()
      with:
        sarif_file: trivy-results.sarif
        category: trivy
```

### `.trivyignore` Template

```
# Acceptable risks — documented justification required

# Example: CVE-2024-XXXX in transitive dependency — no fix available, low exploitation risk
# CVE-2024-1234
```

### Trivy Scanners

Trivy filesystem mode (`fs`) detects:
- **Vulnerabilities** in dependencies (CVEs)
- **Misconfigurations** in IaC files (Dockerfile, docker-compose, Terraform)
- **Secrets** in source code (hardcoded credentials)

For this plan, we only use `--scanners vuln` — dependency vulnerability detection. Misconfig and secrets are handled in later phases.

### Severity Threshold

- **CRITICAL** — immediate fix required, blocks merge
- **HIGH** — fix within sprint, blocks merge
- **MEDIUM** — posted to Security Tab, does NOT block
- **LOW** — informational only

`--severity CRITICAL,HIGH --exit-code 1` makes the job fail on CRITICAL or HIGH.

### `ignore-unfixed` Flag

`--ignore-unfixed: true` ignores vulnerabilities that have no available fix. This prevents the CI from failing on issues the team cannot immediately resolve. The findings are still uploaded to GitHub Security Tab for tracking.

## Tasks

### Task 1: Create `.trivyignore`
**What:** Create empty `.trivyignore` file with documentation comments explaining format and usage.
**Test approach:** File exists, contains comments explaining CVE exclusion process.
**Validation:** `.trivyignore` at project root. Comments explain format (`CVE-YYYY-NNNN`).

### Task 2: Add `sca-trivy` job to `ci.yml`
**What:** Append the `sca-trivy` job to `.github/workflows/ci.yml`. No `needs:` — runs in parallel with other jobs. Uses `aquasecurity/trivy-action@master`.
**Test approach:** Validate YAML syntax. Verify `security-events: write` permission. Verify `scan-type: fs`, `severity: CRITICAL,HIGH`, `exit-code: "1"`, `ignore-unfixed: true`. Verify SARIF upload with `category: trivy`.
**Validation:** Job exists in ci.yml. No `needs:` key. All steps present. Permissions correct. Trivy action parameters correct.

### Task 3: Validate Trivy scan on current codebase
**What:** Run Trivy locally (via Docker) or in CI to detect current dependency vulnerabilities. Document findings: CVE IDs, affected packages, severity, fix version.
**Test approach:** 
- Option A: `docker run --rm -v /var/run/docker.sock:/var/run/docker.sock -v $(pwd):/root/.cache/ aquasec/trivy fs --scanners vuln --severity CRITICAL,HIGH .`
- Option B: Push to branch, let CI run Trivy job.
**Validation:** Scan completes. Findings documented. If CRITICAL or HIGH found, either fix dependency version or add to `.trivyignore` with justification.

### Task 4: Test threshold enforcement
**What:** Verify that the job fails when CRITICAL or HIGH vulnerabilities are present. Can test by temporarily removing `ignore-unfixed` flag or by scanning a known-vulnerable project.
**Test approach:** Add a vulnerable package to a test `package.json` (e.g., an old version of `axios` with known CVEs). Run Trivy scan — verify exit code 1. Revert the change.
**Validation:** Trivy exits with code 1 on vulnerable codebase. Exits with 0 on clean codebase.

## Task Order

Sequential:
- **Task 1:** Create .trivyignore (parallel with Task 2)
- **Task 2:** Add sca-trivy job to ci.yml
- **Task 3:** Validate scan on current codebase (depends on Task 2)
- **Task 4:** Test threshold enforcement (depends on Task 3)

## Risk Assessment

| Risk | Probability | Impact | Mitigation |
|------|------------|--------|------------|
| Trivy scan takes >5 minutes | Low | Low | Filesystem scanning is fast (~30-60s for this project size). Container scanning is slower but not used in this plan. |
| False positives from transitive dependencies | Medium | Medium | `.trivyignore` with documented justification. Track and monitor. |
| No vulnerabilities found on first scan | Low | Low | Expected behavior — codebase may be clean. Run periodically to catch new CVEs. |
| Critical vulnerabilities in production dependencies | Low | High | Immediate fix or dependency update. Block merge until resolved. |
