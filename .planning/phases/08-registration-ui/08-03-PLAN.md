<task type="auto">
  <name>Task 1: Create API client for registration endpoint</name>
  <files>frontend/src/lib/api.ts</files>
  <action>
    Create a typed API client function for the registration endpoint.
    
    Implementation:
    - Export `async function registerClient(data: RegisterClientRequest): Promise<{ id: string }>`
    - Uses native fetch (not axios/ky — keep it simple for now)
    - POST to `/api/registration` (relative URL — same origin in dev via Docker proxy)
    - Headers: { "Content-Type": "application/json" }
    - Body: JSON.stringify(data)
    - On 201: parse response body, return { id }
    - On 422: parse ValidationProblemDetails, throw `RegistrationValidationError(errors)`
    - On 409: throw `DuplicateClientError("A client with the provided information already exists.")`
    - On 503: throw `RegistrationUnavailable("Please try again in a few moments.")`
    - On other errors: throw `ApiError("An unexpected error occurred.")`
    
    Custom error classes (all extend Error):
    - `export class RegistrationValidationError extends Error { constructor(public errors: Record<string, string[]>) }`
    - `export class DuplicateClientError extends Error {}`
    - `export class RegistrationUnavailable extends Error {}`
    - `export class ApiError extends Error {}`
    
    RegisterClientRequest type:
    - Define interface matching the C# DTO: { nome?, cpf?, razaoSocial?, cnpj?, email?, phone?, password? }
    
    What to avoid:
    - Don't use ky or axios — native fetch is sufficient and adds no dependencies
    - Don't include auth headers — this is a public endpoint
    - Don't retry on 4xx errors — only retry on network failures if needed (not in this plan)
  </action>
  <verify>
    1. npx tsc --noEmit passes
    2. registerClient({ nome: "João", cpf: "12345678901", email: "test@test.com", phone: "11999999999", password: "Test@1234" }) — mocks work
    3. Error classes are distinct and catchable
  </verify>
  <done>registerClient function calls API, throws typed errors for each response code</done>
</task>

<task type="auto">
  <name>Task 2: Wire forms to API call + error handling + success redirect</name>
  <files>frontend/src/components/molecules/PfRegistrationForm.tsx, frontend/src/components/molecules/PjRegistrationForm.tsx, frontend/src/components/pages/RegistrationPage.tsx</files>
  <action>
    Update both forms to call the API and handle responses. RegistrationPage manages the submission state and redirect.
    
    RegistrationPage.tsx changes:
    - Add state: `const [isSubmitting, setIsSubmitting] = useState(false)`
    - Add state: `const [submitError, setSubmitError] = useState<string | null>(null)`
    - Add state: `const [fieldErrors, setFieldErrors] = useState<Record<string, string[]> | null>(null)`
    - Create handlePfSubmit function:
      - setIsSubmitting(true), clear errors
      - Call registerClient(data) wrapped in try/catch
      - On success: navigate('/login') (use useNavigate from TanStack Router)
      - On RegistrationValidationError: setFieldErrors(error.errors), map to field-level errors
      - On DuplicateClientError: setSubmitError(error.message)
      - On RegistrationUnavailable: setSubmitError(error.message)
      - On ApiError: setSubmitError(error.message)
      - Finally: setIsSubmitting(false)
    - Create handlePjSubmit function (same logic, different data type)
    - Pass isSubmitting and fieldErrors down to the form components
    - Display submitError above the form if present (use a styled div with text-red-600)
    
    PfRegistrationForm.tsx changes:
    - Add props: `isSubmitting?: boolean`, `fieldErrors?: Record<string, string[]>`
    - Map fieldErrors to form errors: useEffect that calls setError for each field in fieldErrors
      ```ts
      useEffect(() => {
        if (fieldErrors) {
          Object.entries(fieldErrors).forEach(([field, messages]) => {
            setError(field as any, { type: 'server', message: messages[0] })
          })
        }
      }, [fieldErrors, setError])
      ```
    - Map PF field names: nome → errors.nome, cpf → errors.cpf, email → errors.email, phone → errors.phone, password → errors.password
    
    PjRegistrationForm.tsx changes:
    - Same pattern but field names: razaoSocial, cnpj, email, phone, password
    
    What to avoid:
    - Don't use alert() or toast for errors — use inline form errors
    - Don't clear form on success — let navigation handle the unmount
    - Don't retry on 4xx errors — show the error and let user correct
    - Don't expose internal error details from 409/503 (SEC-08) — use the generic messages from API
  </action>

    4. Submit invalid data → 422 → shows field-level errors inline
    5. Submit during Keycloak outage → 503 → shows "Please try again in a few moments."
  </verify>
