# Plan 24-02 — Dockle Container Linting + Best Practices Validation

## Overview

Integrate Dockle into the CI pipeline for container image security linting. Dockle checks Docker images against CIS Benchmarks and best practices: no `latest` tags, no secrets in env vars, proper HEALTHCHECK, non-root user, minimal base images, etc.

## Success Criteria

1. ✅ `container-lint-dockle` job in `ci.yml` builds backend Docker image and runs `dockle` scan
2. ✅ Dockle fails on ERROR-level findings (CKV_DOCKER_1 through CKV_DOCKER_27)
3. ✅ WARNING-level findings posted to CI log but do not block merge
4. ✅ Image built in CI step before scanning — same image as Trivy scan
5. ✅ Dockle uses `goodwithtech/dockle-action@v1` (official action)

## Scope

### In Scope
- `container-lint-dockle` job in `.github/workflows/ci.yml`
- Docker build step (same image as Trivy scan — reuse or rebuild)
- Dockle scan with ERROR severity threshold
- Results output to CI log

### Out of Scope
- Fixing all Dockle findings — some may be acceptable trade-offs (e.g., HEALTHCHECK may not be configured yet)
- Custom Dockle rules — built-in CIS Benchmarks are sufficient
- Frontend container scanning — no Dockerfiles for frontend projects yet
- Keycloak image scanning — not our image to manage

## Technical Details

### CI Job

```yaml
container-lint-dockle:
  name: Container Lint — Dockle
  runs-on: ubuntu-latest
  permissions:
    contents: read
  steps:
    - uses: actions/checkout@v4

    - name: Build backend Docker image
      run: |
        if [ -f Dockerfile ]; then
          docker build -t onboarding-api:ci .
        elif [ -f src/Onboarding.API/Dockerfile ]; then
          docker build -t onboarding-api:ci -f src/Onboarding.API/Dockerfile .
        else
          echo "No Dockerfile found — skipping dockle scan"
          exit 0
        fi

    - name: Run Dockle scan
      uses: goodwithtech/dockle-action@v1
      if: hashFiles('Dockerfile', 'src/Onboarding.API/Dockerfile') != ''
      with:
        image: onboarding-api:ci
        exit-code: "1"
        exit-level: error
        timeout: "5m"
```

### Dockle Checks (Key Rules)

| Check ID | Description | Severity |
|----------|-------------|----------|
| CIS-DI-0001 | Create a user for the container | WARN |
| CIS-DI-0002 | Use trusted base image | FATAL |
| CIS-DI-0003 | Do not use `latest` tag | FATAL |
| CIS-DI-0004 | Use `apt-get update` and `apt-get install` in same RUN | FATAL |
| CIS-DI-0005 | Enable Content Trust | WARN |
| CIS-DI-0006 | Add HEALTHCHECK instruction | WARN |
| CIS-DI-0008 | Confirm safety of setuid/setgid | WARN |
| CIS-DI-0009 | Do not use `ADD` instruction (use COPY) | FATAL |
| CIS-DI-0010 | Do not store secrets in environment variables | FATAL |

### Error vs Warning Handling

- **FATAL/ERROR**: `--exit-level: error` makes Dockle exit with code 1 — blocks merge
- **WARN**: Posted to CI log but does not fail the job
- **INFO**: Informational only

**Validation:** Dockle scan completes. Findings listed with severity. FATAL/ERROR findings cause exit code 1.
