## Technical Details

### Security Runbook Structure

1. **Daily Operations**
   - What to check each morning
   - How to read CI failure messages
   - Where to find security alerts (GitHub Security Tab)

2. **Alert Response by Tool**
   - Semgrep: How to read findings, fix code patterns, use `// nosem`
   - CodeQL: How to interpret dataflow findings, when to suppress
   - Trivy: How to update vulnerable dependencies, when to ignore
   - Dockle: How to fix Dockerfile issues, acceptable deviations
   - Checkov: How to fix Compose misconfigs, suppression process
   - Gitleaks: How to handle detected secrets, immediate revocation
   - TruffleHog: How to verify if secret is active, rotation steps

3. **False Positive Handling**
   - When is something a false positive?
   - How to document and suppress
   - Review process for suppressions (quarterly)

4. **Weekly Security Review**
   - When: Monday 10am, 30 minutes
   - Who: Tech lead + rotating developer
   - Agenda: Review new alerts, dismiss FPs, address open findings
   - Output: Action items, updated suppressions

5. **Escalation Matrix**
   - Level 1 (Developer): Fix own mistakes within 24h
   - Level 2 (Tech Lead): Complex findings, architecture decisions
   - Level 3 (CTO): Production exposures, regulatory impact

6. **Tool Reference**
   - Local run commands for each tool
   - Config file locations
   - Documentation links
