<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Backend → Keycloak Admin API | Backend calls Keycloak Admin REST API with service account credentials |
| Keycloak → JWT | Keycloak signs JWTs with realm private key; groups claim reflects actual group memberships |
| JWT → Backend | Backend validates JWT signature and extracts groups claim for authorization |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-39-01 | S (Spoofing) | JWT groups claim | mitigate | JWT signature validated by JwtBearer middleware — groups claim cannot be forged without realm private key |
| T-39-02 | E (Elevation) | AddUserToGroupAsync | mitigate | Endpoint requires BearerClient auth + CompanyId match (D-17, D-18) — only PJ/admin-empresa can assign groups |
| T-39-03 | T (Tampering) | Group name mapping | mitigate | Group names are static (admin-empresa, viewer, dashboard) — validated against AccessGroup.CreateDefaultGroups() pattern |
| T-39-04 | I (Info disclosure) | GetGroupByNameAsync | accept | Returns only public group metadata (ID, name) — no sensitive data exposed |
| T-39-05 | D (Denial) | CreateGroupAsync idempotent | mitigate | Idempotent design prevents duplicate group creation race conditions |
</threat_model>
