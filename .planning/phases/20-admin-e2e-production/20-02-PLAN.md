# Phase 20 — Plan 02: LGPD Deletion Flow

## Objective

Implementar fluxo de delecao LGPD no backoffice com dialog de confirmacao forte (usuario deve digitar o email exato), integracao com endpoint DELETE, e refresh automatico da tabela. O backend ja anonima dados no PostgreSQL + deleta usuario no Keycloak — o frontend precisa expor isso com UX segura.

## Execution Context

**Strategy:** Test-first — padrao do projeto.

**Backend ready:** DELETE /api/admin/users/{id} ja existe (Phase 16), com `DeleteUserCommand`, `DeleteUserCommandHandler`, e `DeleteUserCommandValidator`. O handler anonima dados no PostgreSQL e deleta no Keycloak.

**What needs to be added:**
- `deleteUser(id)` em `admin-api.ts`
- DeleteDialog com email confirmation
- Botao "Delete" na UsersTable e UserDetailPage
- Toast + table refresh apos sucesso

**What NOT to touch:**
- Backend DELETE endpoint (ja funciona)
- Edit form, block/unblock (Phase 20 Plan 01)
- Client frontend

## Context

**Backend API contract (Phase 16):**
```
DELETE /api/admin/users/{id}
  Response: 204 No Content | 404 Not Found | 409 Conflict (already deleted)
```

**LGPD compliance:**
- Delecao e permanente — nao ha undo
- Backend anonima dados no PostgreSQL (nome, email, documento → placeholder values)
- Backend deleta usuario no Keycloak via Admin API
- Response 204 = sucesso, 409 = usuario ja deletado
- Usuario deletado aparece com `deletedAt` setado no `UserSummaryDto`

**Prior decisions:**
- Sonner para toasts
- shadcn/ui dialog component disponivel
- Admin auth via cookies httpOnly
- Table ja filtra ou marca usuarios deletados
