# Phase 17 — Admin Auth & Session Management

## Plan 01: Cookie Auth Middleware & Admin Login

### Context

Phase 16 criou os endpoints admin (`/api/admin/users`) protegidos por `[Authorize(Roles = "admin")]`, mas ainda não existe um mecanismo de login admin baseado em cookies. A autenticação atual (Phase 6) usa Bearer JWT — adequado para usuários regulares, mas o backoffice admin requer httpOnly cookies para segurança contra XSS.

**Existing infrastructure:**
- `AuthController.cs` já implementa login/refresh/logout/me com cookies httpOnly para usuários regulares (Path=/api)
- `CookieSettings.cs` já existe com `Secure` property (IOptions pattern)
- JWT validation já configurada em Program.cs com `AddJwtBearer`
- Keycloak token service (`IKeycloakTokenService`) já funcional para ROPC grant

**Key difference for admin:**
- Admin login também usa ROPC grant, mas valida que o usuário tem role "admin" no Keycloak
- Cookie Path deve ser `/api/admin` (mais restritivo que `/api`)
- SameSite=Strict (mais seguro que Lax usado para usuários regulares)

### Requirements for this Plan

**ADMIN-06 — HttpOnly Cookie Authentication:**
- Admin login usa cookies httpOnly, Secure, SameSite=Strict
- Nenhum JWT exposto no localStorage ou sessionStorage do frontend
- Cookie configurado com path `/api` e expiry adequado

#### Task 2: Admin Login Handler — ROPC + Role Check
**Files to create:**
- `src/Onboarding.Application/Auth/Handlers/AdminLoginCommandHandler.cs`

**Details:**
1. Recebe `AdminLoginCommand` (email + password)
2. Chama `IKeycloakTokenService.ExchangeROPCAsync(email, password)` — same as regular login
3. Se sucesso, decodifica JWT para extrair roles (ou chama Keycloak Admin API para verificar roles)
4. Verifica se role contém "admin" — se não, lança `UnauthorizedAccessException("Access denied: admin role required")`
5. Se admin, retorna `AdminSessionResponse` com:
   - `RefreshToken` (para colocar no cookie)
   - `ExpiresIn` (refresh token expiry)
   - `AdminName` (nome do admin para exibir no header)
   - `AdminEmail`

**Integration with existing code:**
- Reutiliza `IKeycloakTokenService` já existente
- Pode usar `Keycloak.Admin.Sdk` para verificar roles via Admin API se necessário

**Tests:**
- `src/Onboarding.API.Tests/AdminAuth/AdminLoginHandlerTests.cs`:
  - Valid admin credentials → returns 200 with session data
  - Valid credentials but non-admin user → throws UnauthorizedAccessException
  - Invalid credentials → throws KeycloakAuthException

#### Task 3: AdminAuthController — Login/Logout/Me Endpoints
**Files to create:**
- `src/Onboarding.API/Controllers/AdminAuthController.cs` (ou adicionar ao existente)

**Endpoints:**

```csharp
[ApiController]
[Route("api/admin/[controller]")]
public sealed class AdminAuthController : ControllerBase
{
    // POST /api/admin/auth/login
    [HttpPost("login")]
    public async Task<IActionResult> Login([FromBody] AdminLoginRequest request, CancellationToken ct)
    {
        // 1. Validate request
        // 2. Execute AdminLoginCommand
        // 3. Set refresh token as httpOnly cookie:
        //    - HttpOnly = true
        //    - Secure = _cookieSettings.Secure (from IOptions)
        //    - SameSite = SameSiteMode.Strict
        //    - Path = "/api/admin"
        //    - Expires = DateTimeOffset.UtcNow.AddSeconds(response.RefreshExpiresIn)
        // 4. Return { adminName, adminEmail } (NO tokens in body)
    }

    // POST /api/admin/auth/logout
    [HttpPost("logout")]
    public IActionResult Logout()
    {
        // Delete admin session cookie
        Response.Cookies.Delete("adminRefreshToken", new CookieOptions { Path = "/api/admin" });
        return NoContent();
    }

    // GET /api/admin/auth/me
    [HttpGet("me")]
    public async Task<IActionResult> GetMe(CancellationToken ct)
    {
        // 1. Read "adminRefreshToken" cookie
        // 2. If missing → 401
        // 3. Call IKeycloakTokenService.RefreshAsync(token)
        // 4. If success → update cookie + return { adminName, adminEmail }
        // 5. If failed → delete cookie + 401
    }
}
```

**Cookie name:** `adminRefreshToken` (diferente do `refreshToken` de usuário regular para evitar colisão)

**Tests:**

  - POST /api/admin/auth/logout → 204, cookie cleared
  - GET /api/admin/auth/me with valid cookie → 200 with admin data
  - GET /api/admin/auth/me without cookie → 401
