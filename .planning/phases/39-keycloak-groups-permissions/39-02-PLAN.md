    **4. Create PermissionAuthorizationHandler** (new file: `src/Onboarding.API/Security/PermissionAuthorizationHandler.cs`):

    Implements `AuthorizationHandler<PermissionRequirement>`. Receives `ICurrentCompanyPermissionsService` via DI. Checks if the current user's permissions list contains the required permission string (e.g., "employees:read").

    ```csharp
    public class PermissionRequirement : IAuthorizationRequirement
    {
        public string Permission { get; }
        public PermissionRequirement(string permission) => Permission = permission;
    }

    public sealed class PermissionAuthorizationHandler : AuthorizationHandler<PermissionRequirement>
    {
        private readonly ICurrentCompanyPermissionsService _permissionsService;

        protected override Task HandleRequirementAsync(
            AuthorizationHandlerContext context, PermissionRequirement requirement)
        {
            if (_permissionsService.Permissions.Contains(requirement.Permission))
                context.Succeed(requirement);

            return Task.CompletedTask;
        }
    }
    ```

    **1. Create ClientClaimsMiddleware** (new file: `src/Onboarding.API/Middleware/ClientClaimsMiddleware.cs`):

    Extension method `UseClientClaims()` that runs AFTER `UseAuthentication()` and BEFORE `UseAuthorization()`.

    Logic per request (BearerClient scheme only, per D-09, D-10, D-11):
    1. Skip if request path starts with `/api/admin` (backoffice routes use AdminSessionMiddleware)
    2. Skip if user is NOT authenticated → no need to resolve company/permissions
    3. Read JWT `sub` claim from `User.FindFirst("sub")?.Value`
    4. If no `sub` → set CompanyId = Guid.Empty, skip (403 downstream)
    5. Look up `Company` by `KeycloakUserId == sub` via `ICompanyRepository.GetByKeycloakSubAsync()`
       - If NO company found → also check `Employee` by `KeycloakUserId == sub` (employee login)
       - If no match at all: set CompanyId = Guid.Empty → HasQueryFilter returns nothing → 403
    6. If company found (PJ owner):
       - Set `ICurrentCompanyService.CompanyId = company.Id`
       - Set `ICurrentCompanyPermissionsService.CompanyId = company.Id`
       - Set `ICurrentCompanyPermissionsService.IsCompanyOwnerFlag = true`
       - Set `ICurrentCompanyPermissionsService.PermissionList = Permissions.All.ToList()` (D-20: PJ owner gets all permissions)
    7. If employee found:
       - Get the employee's `AccessGroupId`
       - Look up `AccessGroup` by ID
       - Set `ICurrentCompanyPermissionsService.CompanyId = employee.CompanyId`
       - Set `ICurrentCompanyPermissionsService.IsCompanyOwnerFlag = false`
       - Set `ICurrentCompanyPermissionsService.PermissionList = accessGroup.Permissions.ToList()`
       - Also set `ICurrentCompanyService.CompanyId = employee.CompanyId` (for HasQueryFilter)
    8. If company/employee not found: CompanyId = Guid.Empty → 403

    Use scoped services from DI: `ICompanyRepository`, `IEmployeeRepository`, `IAccessGroupRepository`, `ICurrentCompanyService`, `ICurrentCompanyPermissionsService`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| JWT → ClientClaimsMiddleware | Middleware must trust JWT signature (already validated by JwtBearer) but must NOT trust claims without DB verification |
| ClientClaimsMiddleware → DB | DB lookup for Company/Employee by KeycloakUserId — trust database as source of truth |
| PermissionAuthorizationHandler → ICurrentCompanyPermissionsService | Handler trusts the scoped service (set by middleware) — permissions come from DB, not JWT directly |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-39-06 | E (Elevation) | ClientClaimsMiddleware | mitigate | PJ owner detection compares Company.KeycloakUserId == JWT sub from DB — not from JWT claim alone; if sub not found in DB, gets Guid.Empty → 403 |
| T-39-07 | E (Elevation) | PermissionAuthorizationHandler | mitigate | Permissions come from DB AccessGroup lookup, not JWT groups claim directly (D-04). JWT groups used only as hint, actual permissions resolved by middleware from DB |
| T-39-08 | T (Tampering) | Group name to permission mapping | mitigate | AccessGroup.Permissions are DB-enforced (D-04, T-37-04). Updating permissions requires AccessGroup.UpdatePermissions() which validates against Permissions.All |
| T-39-09 | I (Info disclosure) | HasQueryFilter with Guid.Empty | mitigate | When CompanyId=Guid.Empty (unauthenticated/unknown), HasQueryFilter returns empty result set — no data leakage (D-17) |
| T-39-10 | D (Denial) | Middleware DB lookup on every request | accept | One DB query per request (Company lookup by KeycloakUserId). Acceptable for v7.0 scope. Caching can be added later if needed |
</threat_model>
