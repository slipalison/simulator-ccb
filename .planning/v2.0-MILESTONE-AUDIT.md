## Critical Gaps

### OBS-05: Health Check Endpoints Not Merged

**Severity:** Critical (blocker)  
**Affected Phase:** 04 Observability, Plan 04-02  
**Root Cause:** The health check implementation was completed in worktree branch `worktree-agent-acd23163` (commit `4dd8ef8`) but was **never merged** to the `master` branch.

**What is missing on master:**
- `Program.cs` lacks `AddHealthChecks()` and `MapHealthChecks("/healthz/live", "/healthz/ready")`
- `Program.cs` lacks `WriteDetailedJson` health check response configuration
- `Onboarding.API.csproj` is missing NuGet references:
  - `AspNetCore.HealthChecks.NpgSql` (PostgreSQL dependency health)
  - `AspNetCore.HealthChecks.Uris` (external dependency health checks)
- Test file `HealthCheckEndpointTests.cs` contains **5 RED stub tests** — tests that assert `true.ShouldBeFalse(...)` as placeholders for unimplemented verification

**Impact:**
- `compose.yaml` references `/healthz/live` as the container health check endpoint
- The compiled binary does not expose this endpoint
- Docker would mark the `api` container as **unhealthy** at runtime
- Orchestrators relying on health probes would continuously restart the container

**Resolution Path:**
1. Merge the worktree branch: `git merge worktree-agent-acd23163` or cherry-pick: `git cherry-pick 4dd8ef8`
2. Replace RED stub tests in `HealthCheckEndpointTests.cs` with real assertions
3. Verify endpoints respond with 200 OK before and after dependencies are ready

## Tech Debt

### Phase 04: Observability
- **E2E trace tests skipped** — `TracePropagation` tests marked `[Fact(Skip=...)]` because they require a running Grafana Tempo stack. Verified manually but not automated.
- **5 RED stub tests in HealthCheckEndpointTests.cs** — Placeholder assertions (`true.ShouldBeFalse(...)`) that always fail. Should be replaced with real health check endpoint tests once OBS-05 is merged.

### Phase 05: Registration API
- **4 HealthCheck tests fail due to missing Keycloak config in test factories** — `HealthyApiFactory` and `UnhealthyApiFactory` do not configure Keycloak settings that `AddInfrastructure()` requires. This is a regression from Phase 5's `AddInfrastructure` addition. Not a blocker for the Phase 5 goal, but causes red tests in CI.

### Phase 07: Frontend Foundation
- **Zod v4 installed instead of v3** — The plan specified Zod v3 but v4 was installed. The API is compatible and tests pass, but the version mismatch should be documented or the plan updated.
- **`console.log` in ExampleForm onSubmit** — Intentional no-op in the form submission handler. Should be replaced with real API integration or removed.

### Phase 11: UX Redesign
- **Stale test comments in `password-strength.test.ts`** — Test file still contains "stub - should fail" comments from earlier TDD iterations. Non-functional but misleading for future developers.
- **Resend.com API key needs `.env` configuration** — Email delivery for password reset requires `RESEND_API_KEY` to be set. Currently only works with mock/test mode.
- **Email template customization not implemented** — Password reset emails use default Resend template. Custom branded templates not yet designed.
